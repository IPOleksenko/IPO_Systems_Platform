# Налаштування CAR, MRC та тіньової пам'яті PAM

До того як фізична пам'ять DRAM сможет сохранить хотя бы один байт данных, процесор x86 обязан выполнить тысячи инструкций ініціалізації. **IPO_Boot_ROM** координирует эту сложнейшую цепочку действий.

## ⚡ Этап 1: Механика Cache-as-RAM (CAR)

На современных процесорах внешняя пам'ять DRAM требует сложной калибровки алгоритмами MRC. Чтобы получить возможность вызывать подпрограммы на языке C та использовать стек до увімкнення DRAM, внутренний кэш L1/L2 процесора переводится в режим временной оперативної пам'яті (CAR).

### Последовательность налаштування MTRR:
1. **Вимкнення кэширования:** Сброс битов `CD` (Cache Disable) та `NW` (Not Write-through) в регістре `%cr0`.
2. **Конфігурація MSR MTRRdefType (`0x2FF`):**
   - Сброс бита MTRR Enable (Бит 11) для временного вимкнення активных правил.
   - Установка типа за умолчанию в Uncacheable (`UC`, тип `0x00`).
3. **Налаштування переменного регістра MTRR 0 (`MTRRphysBase0` `0x200`, `MTRRphysMask0` `0x201`):**
   - Base = `0x70000` (Режим Write-Back `0x06`).
   - Mask = `0xFFFF8800` (Valid bit 11 set; creates 32 KB window) (Установлен валидный бит 11; задаёт окно кэширования розміром 32 КБ (0x70000..0x77FFF, SS:SP = 0x7000:0x8000)).
4. **Увімкнення MTRR:** Установка бита 11 в регістре `MTRRdefType`.
5. **Ініціалізація области CAR нулями:** Виконання `rep stosd` за адресиам `0x70000`..`0x77FFF`. Так як активен режим Write-Back, процесор аллоцирует рядка кэша L1/L2 без обращений до внешней шині пам'яті!
6. **Установка вказівника стека:**
```asm
mov esp, 0x8000   ; Повноцінний C-стек усередині кешу CPU!
```

## 🧠 Этап 2: Ініціалізація пам'яті (MRC) та тренировка DRAM

Имея рабочий стек в CAR, IPO_Boot_ROM определяет чипсет та настраивает контролер оперативної пам'яті:

1. **Идентификация моста Host-to-PCI:**
   - Читання Vendor/Device ID с шини 0, пристрої 0, функції 0 (`0x0CF8` / `0x0CFC`).
   - `0x8086:0x1237` $\to$ Intel i440FX (чипсет PCI/IDE).
   - `0x8086:0x29C0` $\to$ Intel Q35 (чипсет PCI Express).
2. **Конфігурація регістров DRAM:** Установка параметрів рядків/колонок, задержек CAS Latency та счетчиков регенерации.
3. **Перевірка ячеек пам'яті:**
   - Запис чередующихся битовых шаблонов (`0x55AA55AA` та `0xAA55AA55`).
   - Считывание та подтверждение отсутствия битовых помилок.

## 🛡️ Этап 3: Тіньова пам'ять PAM та Контракт 2

После перевірки фізичної пам'яті DRAM:

1. **Разблокировка регістров PAM:** Регістры Programmable Attribute Map (наприклад, PAM0 чипсета i440FX, регістр `0x59`) управляют сегментом BIOS `0xF0000`..`0xFFFFF`:
   - Устанавливаются биты `WE = 1` (Разрешена запис) та `RE = 1` (Разрешено читання).
2. **Копирование полезной нагрузки:** Полезная нагрузка `IPO_Firmware` копируется з окна SPI ROM (`0xFFFE0000`) в фізичну пам'ять RAM за адресиу `0x000F0000`.
3. **Перенос стека:** Регістр `%esp` перенаправляется з Cache-as-RAM в физическую конвенциональную пам'ять (наприклад, `0x00007C00`).
4. **Сброс CAR:** Вимкнення регістра MTRR 0 та виконання инструкции `wbinvd` (Write-Back and Invalidate Cache).
5. **Блокировка PAM в Read-Only:** Конфігурація PAM0 с `WE = 0` (Защита від запису) та `RE = 1` (Читання з теневой RAM).
6. **Переход за Контракту 2:** Перевірка сигнатуры `'IPOF'` (`0x464F5049`) за смещению `0xF000:0000` та дальний переход на точку входу:
```asm
jmp 0xF000:0004       ; Вхід в IPO_Firmware (Контракт 2)
```
