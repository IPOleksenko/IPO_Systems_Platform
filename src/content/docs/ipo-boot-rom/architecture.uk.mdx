# Налаштування CAR, MRC та тіньової пам'яті PAM

До того як фізична пам'ять DRAM сможет сохранить хотя бы один байт данных, процесор x86 обязан выполнить тысячи инструкций ініціалізації. **IPO_Boot_ROM** координирует эту сложнейшую цепочку действий.

## ⚡ Этап 1: Механика Cache-as-RAM (CAR)

До ініціалізації DRAM Cache-as-RAM надає Boot ROM тимчасову область пам'яті та стек для виконання коду.

### Послідовність налаштування MTRR:
1. **Підготовка кешу:** Встановити `CR0.CD` і скинути `CR0.NW` перед налаштуванням CAR.
2. **Тип пам'яті за замовчуванням:** Записати `0x800` у `MTRRdefType` (`0x2FF`): MTRR увімкнені, тип за замовчуванням — Uncacheable (`UC`, `0x00`).
3. **Змінний MTRR 0** (`MTRRphysBase0` `0x200`, `MTRRphysMask0` `0x201`): задати режим Write-Back (`0x06`) для області `0x70000`..`0x77FFF`.
4. **Заповнення CAR:** Скинути `CR0.CD` для заповнення кешу. Перші 64 записи dword дозуються через порт `0x80`, решта 8 128 записів заповнюються командою `rep stosd`. Така затримка не гарантує відсутності зависань на фізичних платах.
5. **Відновлення стану кешу та стек CAR:** Знову встановити `CR0.CD`, задати `SS:SP = 0x7000:0x8000` і очистити ще 256 байтів scratch-області.

## 🧠 Этап 2: Memory Reference Code (MRC) та ініціалізація DRAM

Маючи робочий стек у CAR, IPO_Boot_ROM повідомляє модель CPU, виявляє Host Bridge та ініціалізує пам'ять:

1. **Ідентифікація CPU та Host Bridge:**
   - Читання рядка моделі CPU через CPUID (якщо розширені функції недоступні, використовується рядок виробника).
   - Динамічне читання та виведення Vendor ID, Device ID і ревізії Host Bridge на шині PCI 0, пристрій 0, функція 0 (`0x0CF8` / `0x0CFC`); фіксований список ID не використовується.
   - Приклади ID: `0x8086:0x1237` (Intel i440FX) та `0x8086:0x29C0` (Intel Q35).
2. **Визначення обсягу пам'яті:** Читання розширених параметрів пам'яті CMOS; якщо придатний обсяг не вказано, MRC використовує резервне значення 64 МБ.
3. **Налаштування Host Bridge:** Запис регістрів меж DRAM та керування/таймінгів SDRAM, параметрів сторінок і меж TOM/TOLUD, після чого вмикається контролер DRAM. Поточна реалізація не виконує тест пам'яті з чергуванням шаблонів.

## 🛡️ Этап 3: Тіньова пам'ять PAM та Контракт 2

Після ініціалізації DRAM:

1. **Разблокировка регістров PAM:** Регістры Programmable Attribute Map (наприклад, PAM0 чипсета i440FX, регістр `0x59`) управляют сегментом BIOS `0xF0000`..`0xFFFFF`:
   - Установити `WE = 1` і `RE = 0` для відкритого стану PAM під час копіювання в тіньову пам'ять.
2. **Копіювання корисного навантаження:** Повний 64 КБ сегмент ROM (включаючи корисне навантаження `IPO_Firmware` за зміщенням `0xF000:0000`) копіюється з вікна пам'яті ROM (`0xFFFF0000`) у тіньову оперативну пам'ять DRAM Shadow RAM (`0x000F0000`).
3. **Стек під час передачі керування:** Стан передачі використовує `SS:SP = 0x0000:0x7C00`.
4. **Сброс CAR:** Вимкнення регістра MTRR 0 та виконання инструкции `wbinvd` (Write-Back and Invalidate Cache).
5. **Налаштування PAM для читання з тіньової пам'яті:** Встановити `WE = 0` і `RE = 1`; поточний код не зчитує регістр назад для перевірки цього стану.
6. **Переход за Контракту 2:** Перевірка сигнатуры `'IPO'` (`0x004F5049`) за смещению `0xF000:0000` та дальний переход на точку входу:
```asm
jmp 0xF000:0004       ; Вхід в IPO_Firmware (Контракт 2)
```
