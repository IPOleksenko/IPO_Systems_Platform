# Настройка CAR, MRC и теневой памяти PAM

До того как физическая память DRAM сможет сохранить хотя бы один байт данных, процессор x86 обязан выполнить тысячи инструкций инициализации. **IPO_Boot_ROM** координирует эту сложнейшую цепочку действий.

## ⚡ Этап 1: Механика Cache-as-RAM (CAR)

До инициализации DRAM Cache-as-RAM предоставляет Boot ROM временную область памяти и стек для выполнения кода.

### Последовательность настройки MTRR:
1. **Подготовка кэша:** Установить `CR0.CD` и сбросить `CR0.NW` перед настройкой CAR.
2. **Тип памяти по умолчанию:** Записать `0x800` в `MTRRdefType` (`0x2FF`): MTRR включены, тип по умолчанию — Uncacheable (`UC`, `0x00`).
3. **Переменный MTRR 0** (`MTRRphysBase0` `0x200`, `MTRRphysMask0` `0x201`): задать режим Write-Back (`0x06`) для области `0x70000`..`0x77FFF`.
4. **Заполнение CAR:** Сбросить `CR0.CD` для заполнения кэша. Первые 64 записи dword дозируются через порт `0x80`, оставшиеся 8 128 записей заполняются командой `rep stosd`. Такая задержка не гарантирует отсутствия зависаний на физических платах.
5. **Восстановление состояния кэша и стек CAR:** Снова установить `CR0.CD`, задать `SS:SP = 0x7000:0x8000` и очистить ещё 256 байт области scratch.

## 🧠 Этап 2: Memory Reference Code (MRC) и инициализация DRAM

Имея рабочий стек в CAR, IPO_Boot_ROM сообщает модель CPU, обнаруживает Host Bridge и инициализирует память:

1. **Идентификация CPU и Host Bridge:**
   - Чтение строки модели CPU через CPUID (если расширенные функции недоступны, используется строка производителя).
   - Динамическое чтение и вывод Vendor ID, Device ID и ревизии Host Bridge на шине PCI 0, устройство 0, функция 0 (`0x0CF8` / `0x0CFC`); фиксированный список ID не используется.
   - Примеры ID: `0x8086:0x1237` (Intel i440FX) и `0x8086:0x29C0` (Intel Q35).
2. **Определение объема памяти:** Чтение расширенных параметров памяти CMOS; если подходящий объем не указан, MRC использует резервное значение 64 МБ.
3. **Настройка Host Bridge:** Запись регистров границ DRAM и управления/таймингов SDRAM, параметров страниц и пределов TOM/TOLUD, затем включение контроллера DRAM. Текущая реализация не выполняет тест памяти с чередующимися шаблонами.

---

## 🛡️ Этап 3: Теневая память PAM и Контракт 2

После инициализации DRAM:

1. **Разблокировка регистров PAM:** Регистры Programmable Attribute Map (например, PAM0 чипсета i440FX, регистр `0x59`) управляют сегментом BIOS `0xF0000`..`0xFFFFF`:
   - Установить `WE = 1` и `RE = 0` для открытого состояния PAM при копировании в теневую память.
2. **Копирование полезной нагрузки:** Полный 64 КБ сегмент ROM (включая полезную нагрузку `IPO_Firmware` по смещению `0xF000:0000`) копируется из окна памяти ROM (`0xFFFF0000`) в теневую оперативную память DRAM Shadow RAM (`0x000F0000`).
3. **Стек при передаче управления:** В состоянии передачи используется `SS:SP = 0x0000:0x7C00`.
4. **Сброс CAR:** Отключение регистра MTRR 0 и выполнение инструкции `wbinvd` (Write-Back and Invalidate Cache).
5. **Настройка PAM для чтения из теневой памяти:** Установить `WE = 0` и `RE = 1`; текущий код не считывает регистр обратно для проверки этого состояния.
6. **Переход по Контракту 2:** Проверка сигнатуры `'IPO'` (`0x004F5049`) по смещению `0xF000:0000` и дальний переход на точку входа:
```asm
jmp 0xF000:0004       ; Вход в IPO_Firmware (Контракт 2)
```
