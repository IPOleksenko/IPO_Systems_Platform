# CAR Setup, MRC & PAM Shadow

Before DRAM can store a single byte, modern x86 processors must execute thousands of instructions. **IPO_Boot_ROM** coordinates this complex sequence.

## ⚡ Phase 1: Cache-as-RAM (CAR) Mechanics

On modern processors, external physical DRAM requires extensive initialization through Memory Referência Code (MRC). To execute C routines and maintain a call stack before DRAM is online, we configure the CPU's internal L1/L2 caches as temporary memory.

### MTRR Configuration Sequence:
1. **Prepare the cache:** Set `CR0.CD` and clear `CR0.NW` before configuring CAR.
2. **Set the default memory type:** Write `0x800` to `MTRRdefType` (`0x2FF`), enabling MTRRs with the default type set to Uncacheable (`UC`, `0x00`).
3. **Configure variable MTRR 0** (`MTRRphysBase0` `0x200`, `MTRRphysMask0` `0x201`) for the Write-Back (`0x06`) region `0x70000`..`0x77FFF`.
4. **Fill CAR:** Clear `CR0.CD` for cache fills. Pace the first 64 dword stores through port `0x80`, then fill the remaining 8,128 dwords with `rep stosd`. The pacing does not guarantee that physical boards will avoid hangs.
5. **Restore cache state and establish the CAR stack:** Set `CR0.CD` again, use `SS:SP = 0x7000:0x8000`, and clear a further 256-byte scratch area.

## 🧠 Phase 2: Memory Referência Code (MRC) & DRAM Initialization

With an operational stack in CAR, IPO_Boot_ROM reports the CPU identity, discovers the host bridge, and initializes memory:

1. **CPU and Host Bridge Identification:**
   - Reads the CPU brand string through CPUID (falling back to the vendor string when extended brand leaves are unavailable).
   - Reads and reports the host bridge Vendor ID, Device ID, and revision from PCI Bus 0, Device 0, Function 0 (`0x0CF8` / `0x0CFC`) without a hardcoded ID lookup table.
   - Example IDs include `0x8086:0x1237` (Intel i440FX) and `0x8086:0x29C0` (Intel Q35).
2. **Memory Sizing:** Reads extended-memory values from CMOS; if no usable size is reported, the MRC uses a 64 MB fallback.
3. **Host Bridge Configuration:** Programs DRAM row-boundary and SDRAM timing/control registers, row-page and paging-policy settings, and the TOM/TOLUD memory limits, then enables the DRAM controller. The current implementation does not run an alternating-pattern DRAM test.

---

## 🛡️ Phase 3: PAM Shadowing & Contract 2 Handover

After DRAM initialization:

1. **Unlock PAM Registers:** Programmable Attribute Map registers (e.g. PAM0 on i440FX register `0x59`) control the BIOS segment `0xF0000`..`0xFFFFF`:
   - Set `WE = 1` and `RE = 0` for the PAM open state used during shadow copying.
2. **Payload Relocation:** Copy the full 64 KB ROM segment (including the `IPO_Firmware` payload at `0xF000:0000`) from the ROM memory window (`0xFFFF0000`) into DRAM Shadow RAM at `0xF000:0000` (`0x000F0000`).
3. **Set the handover stack:** The handover state uses `SS:SP = 0x0000:0x7C00`.
4. **Teardown CAR:** Disable variable MTRR 0 and execute `wbinvd` (Write-Back and Invalidate Cache).
5. **Configure PAM for read-only shadow access:** Set `WE = 0` and `RE = 1`; the current code does not read back the register to verify this state.
6. **Handover Jump:** Validate header magic `'IPO'` (`0x004F5049`) at `0xF000:0000` and execute far jump to entry point:
```asm
jmp 0xF000:0004       ; Enter IPO_Firmware (Contract 2)
```
