# ABI и соглашения о вызовах

Бинарный интерфейс приложений (ABI) определяет правила взаимодействия между функциями, библиотеками и ядром IPO_OS. Строгое соблюдение соглашений о вызовах гарантирует корректную работу при компоновке модулей.

---

## 🏛️ Соглашение о вызовах C (`cdecl`)

Пользовательский код C для архитектуры x86 (32 бита) в IPO_OS использует стандартное соглашение **cdecl**:

```
Состояние стека перед вызовом функции с тремя аргументами: foo(arg1, arg2, arg3):

Старшие адреса
+---------------+
|     arg3      |  [ebp + 16]
+---------------+
|     arg2      |  [ebp + 12]
+---------------+
|     arg1      |  [ebp + 8]
+---------------+
|  Return EIP   |  [ebp + 4] (Адрес возврата, помещается командой CALL)
+---------------+
|   Saved EBP   |  [ebp]     (Помещается прологом: push %ebp; mov %esp, %ebp)
+---------------+
|  Локальные    |  [ebp - 4], [ebp - 8]...
+---------------+
Младшие адреса (ESP)
```

### Основные правила `cdecl`:
1. **Порядок передачи параметров:** Аргументы помещаются в стек **справа налево**.
2. **Очистка стека:** Стек после возврата очищает **вызывающая сторона** (caller) инструкцией `add esp, N`.
3. **Возвращаемые значения:**
   - 32-битные целые числа и указатели возвращаются в регистре `%eax`.
   - 64-битные числа (`int64_t`, `uint64_t`) возвращаются в паре регистров `%edx:%eax` (`%edx` — старшие 32 бита, `%eax` — младшие).
   - Числа с плавающей запятой возвращаются на вершине стека сопроцессора x87 (`ST(0)`).

---

## 🛡️ Правила сохранения регистров процессора

| Регистр | Категория | Ответственность |
| :--- | :--- | :--- |
| `%eax` | Caller-saved | Временный регистр, возвращаемое значение функции |
| `%ecx` | Caller-saved | Временный регистр, счётчик циклов |
| `%edx` | Caller-saved | Временный регистр, старшая часть 64-битного результата |
| `%ebx` | **Callee-saved** | Обязан сохраняться вызываемой функцией |
| `%esi` | **Callee-saved** | Обязан сохраняться вызываемой функцией |
| `%edi` | **Callee-saved** | Обязан сохраняться вызываемой функцией |
| `%ebp` | **Callee-saved** | Базовый указатель кадра стека; обязан сохраняться |
| `%esp` | **Callee-saved** | Указатель вершины стека; восстанавливается при выходе |

## ⚡ Системный ABI ядра (`int 0x80`)

В отличие от Linux, передающего параметры системных вызовов в регистрах общего назначения (`EBX`, `ECX`, `EDX`, `ESI`, `EDI`, `EBP`), в IPO_OS принят унифицированный **Array Pointer ABI**:

```
Состояние регистров CPU при выполнении 'int 0x80':
  EAX = Номер системного вызова (например, 0x1001)
  EBX = Количество аргументов (uint32_t argc)
  ECX = Указатель на массив аргументов в памяти (uint32_t *argv)
```

### Преимущества системного ABI IPO_OS:
1. **Любое количество параметров:** Вызовы могут принимать произвольное число аргументов без ограничений на количество регистров CPU.
2. **Простой диспетчер ядра:** Ядро валидирует адрес `ECX` и копирует `EBX * 4` байт во внутреннюю структуру.
3. **Экономия регистров:** Регистры `EDX`, `ESI` и `EDI` не портятся при вызове ядра и остаются свободными для пользовательской логики.

## 🔧 Реализация системной обёртки на C

Универсальная C-функция отправки системного вызова:

```c
#include <stdint.h>

int ipo_syscall(uint32_t num, uint32_t argc, uint32_t *argv) {
    int ret;
    __asm__ volatile(
        "int $0x80"
        : "=a"(ret)             /* Вывод: EAX содержит результат */
        : "a"(num),             /* Вход:  EAX = номер вызова */
          "b"(argc),            /* Вход:  EBX = количество аргументов */
          "c"(argv)             /* Вход:  ECX = указатель на массив аргументов */
        : "memory"              /* Барьер памяти */
    );
    return ret;
}
```
