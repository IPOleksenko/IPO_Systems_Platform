# ABI та соглашения про вызовах

Бинарный интерфейс додатків (ABI) определяет правила взаимодействия між функціями, библиотеками та ядром IPO_OS. Строгое соблюдение соглашений про вызовах гарантирует корректную работу при компоновке модулей.

---

## 🏛️ Соглашение про вызовах C (`cdecl`)

Користувачский код C для архитектуры x86 (32 бита) в IPO_OS использует стандартное соглашение **cdecl**:

```
Стан стека перед викликом функції з трьома аргументами: foo(arg1, arg2, arg3):

Старші адреси
+---------------+
|     arg3      |  [ebp + 16]
+---------------+
|     arg2      |  [ebp + 12]
+---------------+
|     arg1      |  [ebp + 8]
+---------------+
|  Return EIP   |  [ebp + 4] (Адрес возврата, помещается командой CALL)
+---------------+
|   Saved EBP   |  [ebp]     (Помещается прологом: push %ebp; mov %esp, %ebp)
+---------------+
|  Локальні     |  [ebp - 4], [ebp - 8]...
+---------------+
Молодші адреси (ESP)
```

### Основные правила `cdecl`:
1. **Порядок передачи параметрів:** Аргументы помещаются в стек **справа налево**.
2. **Очищення стека:** Стек після возврата очищает **вызывающая сторона** (caller) инструкцией `add esp, N`.
3. **Возвращаемые значення:**
   - 32-битные целые числа та вказівники возвращаются в регістре `%eax`.
   - 64-битные числа (`int64_t`, `uint64_t`) возвращаются в паре регістров `%edx:%eax` (`%edx` — старшие 32 бита, `%eax` — младшие).
   - Числа с плавающей запятой возвращаются на вершині стека сопроцесора x87 (`ST(0)`).

---

## 🛡️ Правила сохранения регістров процесора

| Регістр | Категория | Ответственность |
| :--- | :--- | :--- |
| `%eax` | Caller-saved | Временный регістр, возвращаемое значення функції |
| `%ecx` | Caller-saved | Временный регістр, счётчик циклов |
| `%edx` | Caller-saved | Временный регістр, старшая часть 64-битного результата |
| `%ebx` | **Callee-saved** | Обязан сохраняться вызываемой функцією |
| `%esi` | **Callee-saved** | Обязан сохраняться вызываемой функцією |
| `%edi` | **Callee-saved** | Обязан сохраняться вызываемой функцією |
| `%ebp` | **Callee-saved** | Базовый вказівник кадра стека; обязан сохраняться |
| `%esp` | **Callee-saved** | Вказівник вершини стека; восстанавливается при выходе |

## ⚡ Системный ABI ядра (`int 0x80`)

В отличие від Linux, передающего параметри системних викликів в регістрах общего назначення (`EBX`, `ECX`, `EDX`, `ESI`, `EDI`, `EBP`), в IPO_OS принят унифицированный **Array Pointer ABI**:

```
Стан регістрів CPU при виконанні 'int 0x80':
  EAX = Номер системного виклику (наприклад, 0x1001)
  EBX = Кількість аргументів (uint32_t argc)
  ECX = Вказівник на масив аргументів у пам'яті (uint32_t *argv)
```

### Преимущества системного ABI IPO_OS:
1. **Любое количество параметрів:** Вызовы можуть принимать произвольное число аргументов без ограничений на количество регістров CPU.
2. **Простой диспетчер ядра:** Ядро валидирует адреси `ECX` та копирует `EBX * 4` байт во внутреннюю структуру.
3. **Экономия регістров:** Регістры `EDX`, `ESI` та `EDI` не портятся при вызове ядра та остаются свободными для користувачской логики.

## 🔧 Реализация системной обёртки на C

Универсальная C-функція отправки системного виклику:

```c
#include <stdint.h>

int ipo_syscall(uint32_t num, uint32_t argc, uint32_t *argv) {
    int ret;
    __asm__ volatile(
        "int $0x80"
        : "=a"(ret)             /* Вивід: EAX містить результат */
        : "a"(num),             /* Вхід:  EAX = номер виклику */
          "b"(argc),            /* Вхід:  EBX = кількість аргументів */
          "c"(argv)             /* Вхід:  ECX = вказівник на масив аргументів */
        : "memory"              /* Бар'єр пам'яті */
    );
    return ret;
}
```
