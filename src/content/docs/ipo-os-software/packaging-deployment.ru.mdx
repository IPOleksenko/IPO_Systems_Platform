# Упаковка и развертывание

После компиляции программы в плоский бинарный файл (`.bin`) его необходимо поместить в раздел файловой системы `IPO_FS`, чтобы командная оболочка ядра смогла его запустить.

---

## 🛠️ Управление файлами через `tools/disk_editor.py`

Автономная утилита на Python `tools/disk_editor.py` позволяет работать с сырыми образами дисков напрямую без необходимости монтирования через loopback-устройства с правами root:

```bash
# 1. Поместить скомпилированный бинарный файл в директорию /applications
python3 tools/disk_editor.py put hello.bin /applications/hello.bin

# 2. Просмотреть список файлов директории
python3 tools/disk_editor.py ls /applications

# 3. Просмотреть содержимое файла
python3 tools/disk_editor.py cat /applications/hello.bin
```

---

## 📦 Пакетная загрузка через `tools/load_applications.py` и `load_to_disk.sh`

В репозитории `IPO_OS_Software` вы можете наполнить образ виртуального диска всеми скомпилированными приложениями, тулчейном, библиотеками, заголовочными файлами и шрифтами:

```bash
# Через удобный скрипт:
./load_to_disk.sh /path/to/disk.img

# Или напрямую через Python с автоматическим форматированием:
python3 tools/load_applications.py --disk /path/to/disk.img --format
```

Утилита `load_applications.py` автоматически проверяет наличие суперблока `IPO_FS`. Если диск не размечен, она форматирует раздел со смещением LBA 2048 перед развёртыванием каталогов `/applications`, `/lib`, `/include` и `/fonts`.

## 🌐 Загрузка по сети через `hosting_client`

Если IPO_OS запущена с активной сетевой подсистемой (`NET_MODE=tap` или `NET_MODE=user`), файлы можно скачивать прямо из запущенной операционной системы:

```bash
# 1. На хост-системе: запуск HTTP-сервера раздачи файлов сборки
python3 -m http.server 8000 --directory ./build

# 2. В терминале оболочки IPO_OS: загрузка файла через утилиту hosting_client
> /applications/hosting_client 192.168.7.1 8000 /hello.bin
```

## 💾 Запись на физические накопители

Для загрузки системы на реальном оборудовании:

<Callout type="warning" lang="ru" title="Проверяйте целевое устройство">
Всегда сверяйте идентификатор целевого накопителя (`/dev/sdX`) с помощью команды `lsblk` перед выполнением `dd`. Ошибочная перезапись не того диска приведёт к безвозвратной потере данных!
</Callout>

```bash
# Запись образа ОС на USB-флешку или карту CompactFlash
sudo dd if=build/IPO_OS.img of=/dev/sdX bs=4M status=progress conv=fsync
sudo sync
```
