# Архитектура бинарных форматов, загрузчик и модель памяти

В операционной системе IPO_OS реализована гибкая и отказоустойчивая подсистема исполнения программ, ключевым компонентом которой является **Универсальный загрузчик исполняемых файлов** (`exec_load()` в `src/kernel/core/process.c:3469`). Работая в связке с `process_spawn()`, `kmod_load_file()` и подсистемой динамической компоновки `dlopen()`, ядро поддерживает исполнение как ELF32 с автоматической DWARF-рефлексией типов, так и плоских бинарников и скриптов с шебангом, гарантируя защитную верификацию текстовых файлов и быстрое кооперативное переключение памяти процессов.

---

## 🗺️ Карта памяти процессов и организация адресного пространства

Каждое пользовательское приложение в IPO_OS выполняется в 32-битном плоском адресном пространстве. Архитектура памяти разделяет базовую область исполнения, кучу ядра, пулы страниц физической памяти и изолированные динамические кучи процессов:

```
+-------------------------------------------------------------+ Верх памяти RAM
| Изолированные динамические кучи (0x08000000 + slot*stride)  | Выделение через sbrk()
+-------------------------------------------------------------+ 0x08000000 (128 МБ)
| Пул страниц фреймов PMM (memory_map_alloc) / Куча при <128M |
+-------------------------------------------------------------+ 0x05000000 (80 МБ)
| Динамическая куча ядра (kmalloc, емкость 64 МБ)             |
|   • Стеки процессов (по 256 КБ каждый, setup_stack)         |
|   • Буферы образов процессов в памяти ядра (binary_storage) |
|   • Массивы аргументов (argv) и переменные окружения        |
+-------------------------------------------------------------+ 0x01000000 (16 МБ)
| Активная область исполнения приложения (из binary_storage)  |
|   • .bss (Неинициализированные глобальные переменные)        |
|   • .data (Инициализированные глобальные переменные)         |
|   • .rodata (Строковые литералы и константы)                |
|   • .text (Исполняемый машинный код, точка входа 0x00800000)|
+-------------------------------------------------------------+ 0x00800000 (8 МБ)
| Пространство ядра (Код с 0x10000, стек ядра на 0x500000)     |
| Карта E820 на 0x6000, заголовок детекции RAM на 0x8FE0      |
+-------------------------------------------------------------+ 0x00000000
```

## 📦 Поддерживаемые исполняемые и динамические форматы

Платформа IPO_OS поддерживает 6 форматов исполняемых файлов, модулей и скриптов:

### 1. 32-битные исполняемые файлы ELF (`ET_EXEC`, `EM_386`)
При обнаружении сигнатуры ELF (`0x7F 'E' 'L' 'F'`) системный реестр binfmt автоматически передаёт исполнение пользовательскому загрузчику **ELF Loader** (`/applications/elf_loader`):
- **Разбор таблицы программных заголовков:** Анализирует `Elf32_Phdr`, извлекая все загружаемые сегменты `PT_LOAD` (`p_type == 1`).
- **Выделение памяти и выравнивание:** Выделяет буфер под диапазон `max_vaddr - min_vaddr`, выровненный по страницам 4 КБ через `sbrk()`.
- **Загрузка сегментов и релокации:** Считывает сегменты с диска и применяет релокации секций `SHT_REL` (`R_386_32`, `R_386_RELATIVE`), если образ загружен не по базовому адресу.
- **Инициализация `.bss`:** Автоматически обнуляет хвостовые области сегментов, где `p_memsz > p_filesz`.
- **Определение соглашений о вызове и возврат значений:** Детектирует возврат структур через скрытый буфер (`is_entry_struct_return`), находит дескриптор формата возвращаемого значения (`IPOR` сигнатура `0x524F5049`) и регистрирует метаданные в ядре через `SYS_SET_RETURN_VALUE` (0x1029).
- **Быстрый трамплин:** Для бинарников с базовым адресом `0x00800000` без релокаций выполняется мгновенный переход на точку входа (`ehdr.e_entry`) с передачей аргументов и окружения.

### 2. Плоские бинарные образы (`.bin`)
Плоские бинарники не содержат заголовков, таблиц секций или метаданных. Они представляют собой чистый машинный код и данные, скомпонованные для исполнения с базового адреса `0x00800000`:
- Обрабатываются напрямую ядром с помощью **Стандартного bare-metal загрузчика** (`exec_load()`).
- Загружаются монолитно в память процесса с выравниванием по страницам 4 КБ по адресу `0x00800000` (`PROCESS_HEAP_START`, 8 МБ).
- Базовый адрес и точка входа устанавливаются в `0x00800000`.
- Весь образ помечается как сегмент данных (`data_off = 0`, `data_sz = total_memsz`).
- Плоские бинарники исполняются напрямую без накладных расходов на метаданные; код завершения возвращается стандартно через регистр `EAX`.

### 3. Динамический реестр форматов (`binfmt` и `/autorun`)
Для поддержки любых форматов файлов без пересборки ядра в IPO_OS реализован расширяемый реестр исполняемых форматов:
- **Ядерный реестр форматов (`g_binfmt_list`):** Системные вызовы `0x10E0` (`IPO_SYSCALL_BINFMT_REGISTER`), `0x10E1` (`IPO_SYSCALL_BINFMT_UNREGISTER`) и `0x10E2` (`IPO_SYSCALL_BINFMT_LIST`) позволяют регистрировать, удалять и просматривать обработчики форматов.
- **Автоматическая регистрация при загрузке (`/autorun`):** На старте ОС скрипт `/autorun` запускает `/applications/binfmt`, регистрирующий стандартные форматы:
  - `ELF32` (`\x7fELF` со смещения 0) &rarr; `/applications/elf_loader`
  - `LuaBytecode` (`\x1bLua` со смещения 0) &rarr; `/applications/lua`
  - `PythonHashbang` (`#!/applications/python`, `#!/bin/python`, `#python`) &rarr; `/applications/python`
  - `LuaHashbang` (`#!/applications/lua`, `#!/bin/lua`, `#lua`) &rarr; `/applications/lua`
  - `TccHashbang` (`#!/applications/tcc`, `//tcc`, `/*tcc`) &rarr; `/applications/tcc -run`
  - `ShHashbang` (`#!/bin/sh`, `#!/applications/sh`, `#sh`) &rarr; `/applications/sh`
- **Утилита командной строки (`/applications/binfmt`):** Команда `binfmt list` выводит зарегистрированные форматы, а `binfmt add <name> <magic> <offset> <runner>` позволяет подключать новые среды (например, WebAssembly).

### 4. Скрипты с шебангом и тегами
Интерпретируемые скрипты перехватываются на этапе создания процесса через подсистему `binfmt`:
- Поддерживаются как классические шебанги (`#!/path/to/interpreter`), так и теги заголовков (`#python`, `#lua`, `//tcc`).
- Разрешает путь к интерпретатору и параметры запуска динамически.
- Переписывает массив `argv` и рекурсивно запускает интерпретатор.
- Поддерживает глубину вложенности до 16 уровней (`spawn_depth < 16`).

### 5. Динамические модули ядра (`.kmd`, Ring 0)
Загружаются функцией `kmod_load_file()` в `src/kernel/core/kmod.c`:
- **Формат:** Заголовок `kmod_raw_header_t` с сигнатурой `'KMOD'` (`0x444F4D4B`), проверка версии ABI и контрольная сумма CRC32 полезной нагрузки.
- **Динамическое разрешение символов:** Поиск неразрешенных символов в таблице ядра `ksymtab` (~1560 символов) методом бинарного поиска.
- **Релокации:** Коррекция абсолютных (`KMOD_RELOC_ABSOLUTE`) и относительных (`KMOD_RELOC_PCREL`) адресов.
- **Жизненный цикл:** Вызов функций `init()` и `cleanup()`.

### 6. Разделяемые библиотеки и объектные файлы (`.so`, `.o`)
Загружаются в пользовательском пространстве с помощью `dlopen()`, `dlsym()`, `dlclose()` из `IPO_OS_Software/lib/libc/dlfcn.c`:
- **Объектные файлы (`ET_REL`, `.o`):** Размещение секций в памяти, обработка COMMON-символов, применение релокаций секций и экспорт символов.
- **Разделяемые библиотеки (`ET_DYN`, `.so`):** Отображение сегментов `PT_LOAD`, разбор таблицы динамических символов и запуск конструкторов.
- **Режимы связывания:** Поддержка флагов `RTLD_LAZY`, `RTLD_NOW`, `RTLD_GLOBAL` и `RTLD_LOCAL`.

## ⚡ Динамическое выделение в свободное место и переключение контекста без копирования

В IPO_OS многозадачные процессы не копируются поочерёдно в единое статическое окно. Вместо этого каждый процесс размещается в динамически выделенном свободном блоке памяти:

1. **Аллокатор первого подходящего блока (`allocate_process_memory`):**
   - Ядро выполняет поиск в таблице `allocated_blocks` подходящего свободного блока (`pid == 0`) требуемого размера. Если найденный блок больше нужного, он разбивается (`split`), оставляя остаток свободным.
   - Если подходящий блок не найден, память выделяется в свободном месте в конце пула (`PROCESS_HEAP_START + global_process_heap_used`).
2. **Исполнение прямо на месте (In-Place):**
   - Машинный код загружается напрямую в выделенный блок памяти (`proc->binary_base = mem`).
   - Точка входа устанавливается на адрес выделенного свободного блока (`proc->entry_point = (uint32_t)mem`), при этом `proc->binary_storage = NULL`, а `proc->code_mapped = true`.
3. **Переключение контекста без копирования (`process_switch_context`):**
   - Смена активного процесса сохраняет и восстанавливает регистры процессора и указатели стека (`%esp`, `%ebp`, `%ebx`, `%esi`, `%edi`, `eflags`) без накладных расходов на копирование или своп образов в памяти.
   - Функция `process_map_app(proc)` фиксирует указатель `currently_mapped_app` для оконного менеджера и драйверов без перемещения страниц памяти.
4. **Освобождение памяти и объединение блоков:**
   - При завершении процесса `free_process_memory()` помечает блок как свободный (`pid = 0`).
   - Функция `coalesce_free_blocks()` автоматически объединяет соседние свободные блоки в единые непрерывные участки памяти для будущих процессов.

## 📈 Изолированные динамические кучи процессов (`process_heap_init`)

Динамическая память, запрашиваемая через `malloc()` и `sbrk()` (`IPO_SYSCALL_SBRK`, `0x1045`), полностью изолирована:
- **Базовый адрес:** Начинается с `USER_HEAP_START` (`0x08000000`, 128 МБ) или `0x05000000` (80 МБ) на машинах с малым объемом RAM.
- **Динамический шаг (stride):** Вычисляется исходя из общего объема физической RAM (по умолчанию 256 МБ, минимум 32 МБ).
- **Поиск свободного слота:** Ядро динамически находит первый свободный непересекающийся слот среди активных процессов.
- **Старт с нулевым коммитом:** Куча каждого процесса создается с **0 выделенных байт**. Физическая память выделяется по требованию при вызовах `sbrk()`.
- **Освобождение:** При завершении процесса слот кучи и вся выделенная память мгновенно возвращаются системе.

## 🎯 Типизированный возврат из процессов (`process_trampoline`)

Точка входа вызывается через функцию-трамплин ядра `process_trampoline()`:
- **Обработка возврата структур:** Если функция `main()` возвращает структуру (`is_entry_struct_return`), ядро выделяет буфер, заполненный `0xDD`, и передает скрытый указатель первым параметром.
- **Сериализация формата:** После возврата из `main()` ядро по дескриптору `proc->return_format` преобразует возвращенные регистры `EAX:EDX` или буфер структуры в типизированное значение `proc->return_val`:
  - `struct` / пользовательские типы: сериализация полей (например, `{ data: "hello", length: 5 }`).
  - `char*`: считывание строки из памяти пользователя.
  - `float` / `double`: форматирование чисел с плавающей точкой.
  - `int64` / `uint64`: объединение регистров `EAX` и `EDX`.
  - `bool`: значения `true` или `false`.
  - `int`: целочисленный код возврата в `proc->exit_code`.
- Результат отображается в shell и может передаваться в пайпы между процессами.
