# Архитектурный глоссарий

В данном глоссарии собраны определения низкоуровневых технических терминов и понятий архитектуры x86, используемых в проектах **IPO_OS**, **IPO_Boot_ROM** и **IPO_Firmware**.

---

### A20 Gate (Вентиль A20)
Аппаратная линия управления 20-м битом шины адреса (через контроллер клавиатуры `0x64` или Fast Port `0x92`). При отключении адрес циклически заворачивается на 1 МБ (эмуляция 8086). Обязательно активируется для доступа к памяти выше 1 МБ.

### BDA (BIOS Data Area)
Область данных BIOS размером 256 байт по физическому адресу `0x00000400`..`0x000004FF`, хранящая базовое состояние оборудования (адреса портов COM/LPT, буфер клавиатуры, видеорежим).

### CAR (Cache-as-RAM)
Технология инициализации, при которой внутренний кэш L1/L2 процессора настраивается через MSR-регистры MTRR как временная оперативная память до того, как физическая память DRAM будет инициализирована. Позволяет использовать стек и код на языке C.

### Contract 1 (Контракт 1)
Интерфейсный контракт передачи управления от аппаратного вектора сброса CPU (`0xFFFFFFF0`) точке входа Boot ROM.

### Contract 2 (Контракт 2)
Бинарный контракт передачи управления от **IPO_Boot_ROM** в **IPO_Firmware** по физическому адресу `0xF000:0004` после настройки DRAM и блокировки теневой памяти PAM. Валидируется сигнатурой `'IPOF'` (`0x464F5049`).

### Contract 3 (Контракт 3)
Классический контракт загрузки BIOS, по которому **IPO_Firmware** передаёт управление загрузчику операционной системы, считывая сектор MBR по адресу `0x0000:7C00` с регистром `DL` (номер диска) и проверкой сигнатуры `0x55AA`.

### E820 Memory Map
Стандартный сервис прерывания BIOS (`INT 0x15, AX=0xE820`), используемый операционной системой для обнаружения доступных диапазонов физической памяти RAM, зарезервированных областей и ACPI.

### EBDA (Extended BIOS Data Area)
Расширенная область данных BIOS (обычно по адресу `0x9FC00`), резервируемая прошивкой для хранения приватного состояния, таблиц ACPI и структур SMP.

### Extent (Экстент)
Непрерывная цепочка физических секторов диска, выделенная файлу. В файловой системе `IPO_FS` каждый inode хранит четыре первичных 24-байтовых экстента, что обеспечивает максимальную скорость последовательного чтения.

### GDT (Global Descriptor Table)
An x86 processor structure defining flat memory segment base addresses and limits (0x00 Null, 0x08 Code, 0x10 Data) mapping the full 4 GB physical address space in Protected Mode.

### IDT (Interrupt Descriptor Table)
Таблица дескрипторов прерываний процессора x86, содержащая 256 шлюзов для связывания аппаратных прерываний IRQ, исключений процессора и программных вызовов (`int 0x80`) с обработчиками ядра.

### Inode (Индексный дескриптор)
Дисковая структура данных (128 байт в `IPO_FS`), описывающая файл или каталог: метаданные, размер, права доступа и ссылки на цепочки экстентов.

### LBA (Logical Block Addressing)
Логическая адресация блоков, при которой секторы диска нумеруются линейно с 0, заменяя устаревшую геометрию цилиндров, головок и секторов (CHS).

### LFB (Linear Framebuffer)
Линейный кадровый буфер видеокарты, отображаемый в адресное пространство CPU, позволяющий напрямую отрисовывать 32-битные пиксели ARGB без переключения банков памяти.

### MRC (Memory Reference Code)
Низкоуровневый алгоритм инициализации контроллера памяти, выполняющий тайминг-тренировку и калибровку шины DDR DRAM.

### MTRR (Memory Type Range Register)
Специальные моделезависимые регистры CPU (MSR), задающие типы кэширования (Write-Back, Write-Combining, Uncacheable) для конкретных физических диапазонов адресов.

### PAM (Programmable Attribute Map)
Регистры чипсета, управляющие правами чтения и записи в теневую область памяти BIOS (`0x000C0000`..`0x000FFFFF`).

### PMM (Physical Memory Manager)
Архитектура управления физической памятью в IPO_OS: таблица дескрипторов BIOS E820 передаётся по адресу `0x6000` с заголовком `e820_map_header_t` в `0x8FE0` (`'E820'`), куча ядра `kmalloc` занимает 64 МБ (`0x01000000`–`0x04FFFFFF`), страничный аллокатор фреймов (`memory_map_alloc`) работает с `0x05000000+`, а динамические кучи процессов (`sbrk`) разделены на изолированные срезы по 512 МБ начиная с `0x08000000`.

### TSS (Task State Segment)
Legacy x86 hardware task structure. In IPO_OS's flat protected mode model, context switching and system call dispatch are implemented in software routines without hardware TSS stack switching.

### VMM (Virtual Memory Manager)
Подсистема ядра, управляющая каталогами и таблицами страниц, обеспечивая изолированное линейное 4-гигабайтное адресное пространство для каждого процесса.

### KMOD (Relocatable Kernel Module)
Формат динамически загружаемых модулей ядра и драйверов IPO_OS (`.kmd`, сигнатура `'IKMD'` `0x444D4B49`, версия ABI `0x0100`). Поддерживает разрешение ~1560 экспортируемых символов ядра (`generate_ksyms.py`) и 32-битные релокации `ABS32`/`REL32` во время работы системы.

### SMP & Local APIC (Симметричная многопроцессорность)
Архитектура многоядерного исполнения x86, в которой загрузочное ядро (BSP) обнаруживает вторичные ядра (AP) через таблицы ACPI MADT / Intel MP и запускает их по протоколу `INIT-SIPI-SIPI` через регистры MMIO контроллера Local APIC (`0xFEE00000`) и физический трамплин `0x8000`.

### Storage Pool (Многодисковый пул хранения)
Персистентный уровень виртуализации блочных накопителей (`storage_pool.c`), объединяющий несколько физических дисков (`ata0`, `ata1`, ...) в единое линейное логическое том-пространство с первичным и резервным суперблоками в секторах LBA 2030 и LBA 2039 (`'POOL'`, CRC32).

### WAL (Write-Ahead Logging / Журнал предзаписи)
Кольцевой транзакционный журнал из 64 записей по 64 байта в секторах LBA 2031–2038 (`'TXNL'`), фиксирующий операции записи в пул хранения (`PENDING` → `COMMITTED`) для автоматического восстановления целостности после внезапного отключения питания.
