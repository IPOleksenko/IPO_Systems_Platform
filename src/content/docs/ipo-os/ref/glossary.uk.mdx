# Архитектурный глоссарий

В данном глоссарии собраны визначення низкоуровневых технических терминов та понятий архитектуры x86, используемых в проектах **IPO_OS**, **IPO_Boot_ROM** та **IPO_Firmware**.

---

### A20 Gate (Вентиль A20)
Аппаратная линия управления 20-м битом шини адресиа (через контролер клавиатуры `0x64` або Fast Port `0x92`). При отключении адреси циклически заворачивается на 1 МБ (эмуляция 8086). Обязательно активируется для доступа до пам'яті выше 1 МБ.

### BDA (BIOS Data Area)
Область данных BIOS розміром 256 байт за физическому адресиу `0x00000400`..`0x000004FF`, хранящая базовое стан оборудования (адресиа портів COM/LPT, буфер клавиатуры, видеорежим).

### CAR (Cache-as-RAM)
Технология ініціалізації, при якої внутренний кэш L1/L2 процесора настраивается через MSR-регістры MTRR як временная оперативна пам'ять до того, як фізична пам'ять DRAM будет инициализирована. Позволяет использовать стек та код на языке C.

### Contract 1 (Контракт 1)
Интерфейсный контракт передачі керування від аппаратного вектора сброса CPU (`0xFFFFFFF0`) точке входа Boot ROM.

### Contract 2 (Контракт 2)
Бинарный контракт передачі керування від **IPO_Boot_ROM** в **IPO_Firmware** за физическому адресиу `0xF000:0004` після налаштування DRAM та блокировки тіньової пам'яті PAM. Валидируется сигнатурой `'IPOF'` (`0x464F5049`).

### Contract 3 (Контракт 3)
Классический контракт загрузки BIOS, за якому **IPO_Firmware** передаёт управление завантажувачу операційної системи, считывая сектор MBR за адресиу `0x0000:7C00` с регістром `DL` (номер диска) та проверкой сигнатуры `0x55AA`.

### E820 Memory Map
Стандартный сервис переривання BIOS (`INT 0x15, AX=0xE820`), используемый операційною системою для обнаружения доступных диапазонов фізичної пам'яті RAM, зарезервированных областей та ACPI.

### EBDA (Extended BIOS Data Area)
Расширенная область данных BIOS (обычно за адресиу `0x9FC00`), резервируемая прошивкою для хранения приватного стану, таблиц ACPI та структур SMP.

### Extent (Экстент)
Непрерывная цепочка физических секторів диска, выделенная файлу. В файлівій системі `IPO_FS` каждый inode хранит четыре первичных 24-байтовых экстента, что обеспечивает максимальную скорость последовательного читання.

### GDT (Global Descriptor Table)
An x86 processor structure defining flat memory segment base addresses and limits (0x00 Null, 0x08 Code, 0x10 Data) mapping the full 4 GB physical address space in Protected Mode.

### IDT (Interrupt Descriptor Table)
Таблиця дескрипторів переривань процесора x86, содержащая 256 шлюзов для связывания аппаратных переривань IRQ, винятків процесора та программных вызовов (`int 0x80`) с обработчиками ядра.

### Inode (Индексный дескриптор)
Дисковая структура данных (128 байт в `IPO_FS`), описывающая файл або каталог: метаданные, розмір, права доступа та ссылки на цепочки экстентов.

### LBA (Logical Block Addressing)
Логическая адресиация блоков, при якої сектори диска нумеруются линейно с 0, заменяя устаревшую геометрию цилиндров, головок та секторів (CHS).

### LFB (Linear Framebuffer)
Линейный кадровый буфер видеокарты, отображаемый в адресиное пространство CPU, позволяющий напрямую отрисовывать 32-битные пиксели ARGB без переключения банков пам'яті.

### MRC (Memory Reference Code)
Низкоуровневый алгоритм ініціалізації контролера пам'яті, выполняющий тайминг-тренировку та калибровку шини DDR DRAM.

### MTRR (Memory Type Range Register)
Специальные моделезависимые регістры CPU (MSR), задающие типы кэширования (Write-Back, Write-Combining, Uncacheable) для конкретных физических диапазонов адресиов.

### PAM (Programmable Attribute Map)
Регістры чипсета, управляющие правами читання та запису в теневую область пам'яті BIOS (`0x000C0000`..`0x000FFFFF`).

### PMM (Physical Memory Manager)
Memory allocation architecture in IPO_OS: total physical RAM is read from BIOS E820 at 0x8FF0, kernel heap is managed via kmalloc (16 MB at 0x1000000), and dynamic process heaps are partitioned into 64 MB slices.

### TSS (Task State Segment)
Legacy x86 hardware task structure. In IPO_OS's flat protected mode model, context switching and system call dispatch are implemented in software routines without hardware TSS stack switching.

### VMM (Virtual Memory Manager)
Подсистема ядра, управляющая каталогами та таблицами страниц, обеспечивая изолированное линейное 4-гигабайтное адресиное пространство для каждого процесса.
