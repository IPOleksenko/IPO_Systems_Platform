# System Overview & Philosophy

**IPO_OS** is an independent, bare-metal operating system supporting **64-bit x86-64 Long Mode (4-level PML4 / 5-level LA57 paging)** with automatic **32-bit Protected Paged Mode fallback**. Built entirely from scratch, it targets PC-AT compatible personal computers, embedded hardware platforms, and virtual machines without reliance on third-party kernel code or bloated abstraction runtimes.

<Callout type="beginners" title="Why build a bare-metal OS?">
Modern operating systems often hide hardware interactions behind millions of lines of legacy abstractions. IPO_OS strips away opacity: every hardware interrupt, memory block, disk extent, and network frame has an explicit, traceable path from silicon to screen.
</Callout>

## 🎯 Core Design Principles

1. **Direct Hardware Sovereignty:**
   The kernel controls system resources directly through standard x86 ports (`inb`/`outb`), memory-mapped I/O (MMIO), and CPU descriptor tables (GDT, IDT).
2. **Deterministic Monolithic Design:**
   Subsystems for process management, memory management, file systems, device drivers, and networking reside in a unified 32-bit protected-mode address space, ensuring minimal context-switching latency.
3. **Multi-Disk Storage Pool with WAL & Extent-Based Filesystem:**
   Rather than relying on legacy FAT12/16 filesystems, IPO_OS introduces **IPO_FS** — a 64-bit extent-based file system backed by a persistent multi-disk **Storage Pool** (`storage_pool_t`) with redundant primary/backup superblocks (LBA 2030 & 2039, CRC32) and an 8-sector **Write-Ahead Logging (WAL)** transaction journal (LBA 2031–2038).
4. **Symmetric Multiprocessing (SMP):**
   Full multi-core x86 initialization via Local APIC (`0xFEE00000`), dynamic ACPI RSDP/RSDT/MADT and Intel MP table discovery, Application Processor (AP) boot via `INIT-SIPI-SIPI` at physical trampoline `0x8000` (mailbox `0x8180`–`0x81A7`), `spinlock_t` synchronization, and all-core scheduler broadcast IPIs (`0xE0`).
5. **Relocatable Kernel Modules (KMOD) & Dynamic Buffers:**
   Runtime loading of relocatable `.kmd` kernel modules (`IKMD` magic) linked against ~1,700 exported kernel symbols (`generate_ksyms.py`), a Unified Hardware Device Registry (`device.c`), and kernel-wide elimination of fixed-size array limits in favor of self-expanding heap buffers (`krealloc`).
6. **Autonomous Bare-Metal Networking:**
   Includes a native, self-contained **TCP/IP stack** with a full RFC 793/RFC 9293 state machine, modular network driver `/drivers/rtl8139` supporting RTL8139, Intel E1000, and VirtIO-Net over Ethernet/ARP/IPv4/ICMP/TCP/UDP/DHCP/DNS and 16 Net KMD syscalls (`0x12000`–`0x1200F`).
7. **Integrated Graphical and Console Environment:**
   Provides an arbitrary-resolution CRTC console (`cols×rows` from hardware, unlimited glyph sizing via `malloc`) and an RGBA64F HDR Window Manager (WM) with VirtIO-GPU VirGL hardware 3D acceleration, Bochs BGA LFB, and Audio v2 (Intel HDA, AC97, Sound Blaster 16, VirtIO-Sound).

## 🚫 Non-Goals and Explicit Scope Limitations

To preserve architectural clarity and stability, IPO_OS intentionally avoids:
- **Complex Multi-User Trees:** Focuses on single-operator workstation and embedded controller environments.
- **Heavyweight Linux Compatibility Emulation:** Focuses on clean native/POSIX abstractions (305 syscalls including IPC, SHM, pipes, signals, pthreads, futex, and mmap) without legacy Linux bloat.

## 🗺️ Architectural Position in the IPO Platform

IPO_OS represents the top execution layer of the three-tier **IPO Systems Platform**:

<LocalizedDiagram id="global_stack" figureNum={1} />

- **Layer 1: Physical Hardware** — CPU, DRAM, Chipset, Storage, and Peripherals.
- **Layer 2: IPO_Boot_ROM** — Reset vector code, Cache-as-RAM, and DRAM initialization.
- **Layer 3: IPO_Firmware** — BIOS runtime services, IVT, and storage scanning.
- **Layer 4: IPO_OS Kernel** — Resource virtualization and subsystem arbitration.
- **Layer 5: Userspace Applications** — Sandboxed programs running at physical address `0x800000`.
