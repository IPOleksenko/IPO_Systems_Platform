# Прерывания, IDT и таймеры

IPO_OS реализует плоскую 32-битную архитектуру прерываний и ловушек защищённого режима, основанную на **Таблице дескрипторов прерываний процессора (IDT)**, программных шлюзах ловушек для системных вызовов и неблокирующем опросе периферийных устройств.

---

## 🚨 Аппаратные исключения процессора (шлюзы 0–31)

Первые 32 шлюза IDT (`0x00`–`0x1F`) перехватывают сбои и аварии процессора:
- **`#DE` (0x00) — Divide-by-Zero:** деление на ноль или переполнение при целочисленном делении.
- **`#DB` (0x01) — Debug:** аппаратные точки останова (watchpoints) или пошаговое выполнение.
- **`#NMI` (0x02) — Non-Maskable Interrupt:** ошибки чётности памяти или критические сигналы материнской платы.
- **`#BP` (0x03) — Breakpoint:** выполнение инструкции `int 3`.
- **`#UD` (0x06) — Invalid Opcode:** нераспознанная или недопустимая процессорная инструкция.
- **`#DF` (0x08) — Double Fault:** возникновение исключения во время обработки предыдущего исключения.
- **`#GP` (0x0D) — General Protection Fault:** нарушение лимитов сегментов или выполнение привилегированной инструкции.
- **`#PF` (0x0E) — Page Fault:** обращение к несуществующей странице (зарезервировано в плоском режиме).

### Двухуровневый конвейер восстановления при аварии

В файле `src/kernel/syscall/syscall.c` все 32 обработчика исключений указывают на заглушки в `isr_stub_table`, сводящиеся в единую функцию `cpu_exception_handler(uint32_t *frame)`:

```c
void cpu_exception_handler(uint32_t *frame) {
    uint32_t vector   = frame[7];
    uint32_t err_code = frame[8];
    uint32_t eip      = frame[9];
    const char *name  = (vector < 32) ? exception_names[vector] : "Unknown Exception";

    process_t *proc = process_get_current();
    if (proc != NULL) {
        printf("\n[Process %u] Terminated: CPU Exception %u (%s) at 0x%08x (err=0x%x)\n",
               proc->pid, vector, name, eip, err_code);
        serial_printf("[cpu_exception] Process %u crashed: vec=%u (%s) eip=0x%08x err=0x%x\n",
                      proc->pid, vector, name, eip, err_code);
        frame[9] = (uint32_t)process_crash_exit;
        return;
    }

    printf("\nKERNEL PANIC: CPU Exception %u (%s) at 0x%08x (err=0x%x)\n",
            vector, name, eip, err_code);
    while (1) {
        __asm__ volatile("cli; hlt");
    }
}
```

1. **Изоляция пользовательского пространства:** если активный процесс вызывает исключение, ядро перехватывает его, выводит в журнал адрес сбоя `EIP` и код ошибки, и перезаписывает адрес возврата на `process_crash_exit`. Процесс корректно завершается и возвращает управление в терминал.
2. **Паника ядра (Kernel Panic):** если исключение произошло в контексте ядра (`proc == NULL`), система выводит отчёт о панике на экран и в порт COM1, полностью останавливая процессор инструкциями `cli; hlt`.

## ⚡ Программный шлюз прерываний: `int 0x80`

Системные вызовы используют программный шлюз прерываний **`0x80`**:
- Сконфигурирован в IDT с флагами `0xEE` (Present, 32-bit Interrupt Gate, DPL=3).
- Селектор сегмента кода `0x08` (32-битный плоский код ядра).
- Перенаправляет управление на ассемблерную точку входа `syscall_isr_entry` в `src/kernel/arch/x86/syscall.asm`.
- **Аппаратная защита флага прерываний:** В отличие от шлюза-ловушки (Trap Gate), процессор x86 при входе через Interrupt Gate (`0xEE`) автоматически сбрасывает флаг `IF = 0` в EFLAGS, аппаратно запрещая прерывания на время диспетчеризации и исключая реентрантность. Исходное состояние `EFLAGS` восстанавливается инструкцией `iretd`.

## 🔄 Архитектура опроса устройств (Polling)

Вместо использования асинхронной диспетчеризации прерываний PIC IRQ в защищённом режиме, драйверы IPO_OS используют эффективную неблокирующую модель опроса, интегрированную напрямую в главный цикл ядра (`kmain()`):

```c
for (;;) {
    timer_tick();              /* Высокоточный тайминг и квантование времени */
    async_scheduler_tick();    /* Кооперативные обратные вызовы фоновых задач */
    net_poll();                /* Приём и передача пакетов Realtek RTL8139 */
    terminal_console();        /* Опрос ввода шелла и выполнение команд */
}
```

- **Клавиатура и мышь PS/2:** `keyboard_poll()` проверяет порт состояния `0x64` и считывает скан-коды из порта `0x60`. Пакеты мыши накапливаются через `mouse_handle_byte()`.
- **Жёсткий диск ATA:** операции блочного ввода-вывода PIO опрашивают регистр состояния на порту `0x1F7` на предмет битов BSY (Busy) и DRQ (Data Request).
- **Сетевой интерфейс:** функция `net_poll()` вычитывает кольцевые буферы RTL8139 напрямую через порты ввода-вывода и регистры MMIO.

## ⏱️ Отсчёт времени через 8254 PIT и счётчик TSC

1. **Программируемый интервальный таймер 8254 PIT:**
   - Базовая частота генератора: **1.193182 МГц**.
   - Инициализируется частотой **1000 Гц** (`pit_init(1000u)`) в режиме генератора частоты канала 0 (Rate Generator).
2. **Счётчик тактов процессора (TSC):**
   - Текущее время и 10-миллисекундные кванты многозадачности измеряются при помощи инструкции процессора `rdtsc`:
   ```c
   #define TSC_PER_MS 2000000ULL
   ```
   - Обеспечивает субмикросекундную точность измерений времени без аппаратного джиттера прерываний.
