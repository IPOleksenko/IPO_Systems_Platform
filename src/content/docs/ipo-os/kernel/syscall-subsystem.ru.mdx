# Подсистема системных вызовов

Системные вызовы предоставляют защищённый интерфейс, через который пользовательские программы запрашивают сервисы операционной системы без прямого обращения к портам ввода-вывода или структурам ядра.

## 📑 Соглашение о передаче параметров через регистры

IPO_OS использует эффективное соглашение вызова на 3 регистрах через программный шлюз прерываний `int 0x80`:

| Регистр | Роль | Описание |
| :--- | :--- | :--- |
| **`EAX` (Вход)** | Номер системного вызова | 32-битный идентификатор (например, `0x1001` для вывода строки, `0x1012` для чтения) |
| **`EBX` (Вход)** | Количество аргументов (`argc`) | Число 32-битных параметров, переданных в массиве аргументов |
| **`ECX` (Вход)** | Массив аргументов (`argv`) | Указатель на массив параметров `uint32_t` в стеке |
| **`EAX` (Выход)** | Код возврата | `0` или положительное значение при успехе, либо отрицательный код ошибки (например, `-1`) |

## ⚙️ Реализация диспетчеризации в ядре

В файле `src/kernel/syscall/syscall.c` ядро инициализирует таблицу обработчиков:

```c
typedef uint32_t (*ipo_syscall_handler_t)(uint32_t num, uint32_t argc, uint32_t *argv);

void ipo_register_syscall(uint32_t num, ipo_syscall_handler_t handler);
```

### Безопасность и валидация параметров:
1. **Проверка диапазона:** Диспетчер проверяет, что номер в `EAX` зарегистрирован в таблице вызовов. Если вызов не зарегистрирован, возвращается код `IPO_SYSCALL_ENOSYS` (`0xFFFFFFFF`).
2. **Проверка указателей буферов:** Переданные в `argv` пользовательские указатели проверяются на допустимость границ памяти, что исключает модификацию памяти ядра через системные вызовы вроде `read()` или `write()`.
3. **Защита шлюза прерываний:** Шлюз прерываний `int 0x80` (флаги `0xEE`, селектор `0x08`) автоматически сбрасывает `IF = 0` при входе, гарантируя атомарный переход в диспетчер ядра без реентрантности и восстанавливая исходный EFLAGS при `iretd`.
