# Контракт передачи управления от загрузчика

При передаче управления от первичного MBR-загрузчика (`src/boot/boot.asm`) в точку входа ядра IPO_OS (`_start` в `src/kernel/entry32.asm`), состояние процессора и памяти строго соответствует следующему аппаратному контракту.

---

## 📋 Состояние процессора при входе в ядро (0x10000)

Загрузчик подготавливает плоскую 32-битную защищённую модель памяти (Ring 0) без включённой страничной адресации:

| Регистр CPU | Состояние при передаче | Назначение и аппаратный смысл |
| :--- | :--- | :--- |
| **Режим CPU** | 32-битный защищённый режим (Protected Mode) | Уровень привилегий Ring 0, плоская адресация 4 ГБ |
| **`CS`** | `0x08` | Плоский дескриптор кода (база `0x0`, лимит `0xFFFFFFFF`, Ring 0 Exec/Read) |
| **`DS`, `ES`, `SS`, `FS`, `GS`** | `0x10` | Плоский дескриптор данных (база `0x0`, лимит `0xFFFFFFFF`, Ring 0 Read/Write) |
| **`ESP`** | `0x00500000` | Стек ядра размером 5 МБ (устанавливается в `boot.asm` и фиксируется в `entry32.asm`) |
| **`CR0`** | `PE = 1 (бит 0), PG = 0 (бит 31)` | Защищённый режим включён, страничная адресация (Paging) отключена |
| **`EFLAGS`** | `0x00000002` (`IF = 0`) | Аппаратные прерывания запрещены (`cli`) до инициализации таблицы IDT в ядре |
| **`EIP`** | `0x00010000` | Физический адрес точки входа ядра `_start` |
| **Линия A20** | Включена (Fast A20) | Активирована через системный порт `0x92` (`in al, 0x92; or al, 2; out 0x92, al`) |
| **Курсор VGA** | Скрыт | Аппаратный текстовый курсор BIOS отключён перед входом в pmode (`INT 10h, AH=01h, CH=20h`) |

## 🧠 Протокол передачи параметров памяти (Адрес 0x8FF0)

В **IPO_OS** не используются заголовки Multiboot 1/2 или структуры со статическими магическими числами.

Вместо этого загрузчик в реальном режиме опрашивает размер физической оперативной памяти через BIOS `INT 15h, AX=E820` (с автоматическим резервным переключением на `AX=E801`) и суммирует доступный объём. Итоговый размер памяти в байтах записывается напрямую в 32-битную ячейку физической памяти **`0x8FF0`**:

```asm
; Из src/boot/boot.asm:
; detect RAM size using BIOS E820 and store total bytes at 0x8FF0
call detect_memory
```

При старте диспетчера процессов ядро напрямую считывает это значение в `src/kernel/core/process.c`:

```c
static uint64_t get_process_heap_capacity(void) {
    volatile uint32_t *ram_size_ptr = (volatile uint32_t *)0x8FF0;
    uint32_t detected = *ram_size_ptr;
    return (uint64_t)detected;
}
```

## 🚦 Визуальные индикаторы хода загрузки (ARG -> K)

Для аппаратной диагностики на физическом оборудовании без последовательного порта загрузчик и ядро выводят компактные маркеры статуса:

1. **`A`** (`0x41`): Загрузчик проверил расширения дискового BIOS (`INT 13h, AH=41h, BX=55AAh`).
2. **`R`** (`0x52`): Бинарный образ ядра считан с диска начиная с LBA 1 по физическому адресу `0x10000` через DAP (Disk Address Packet, `INT 13h, AH=42h`).
3. **`G`** (`0x47`): Объём памяти определён и записан в `0x8FF0`, выполнена загрузка GDT и переключение в Protected Mode.
4. **`K`** (`0x4B`): Точка входа ядра `_start` записала символ `K` цвета `0x07` (светло-серый на чёрном) в левый верхний угол видеопамяти `0xB8000` непосредственно перед вызовом `kmain()`!

## 🎯 Точка входа ядра (src/kernel/entry32.asm)

Первичный ассемблерный вход ядра состоит ровно из 11 инструкций:

```asm
BITS 32
global _start
extern kmain

_start:
    mov esp, 0x500000
    mov dword [0xB8000], 0x07204B    ; Символ 'K' в левом верхнем углу VGA
    call kmain
.hang:
    hlt
    jmp .hang
```
