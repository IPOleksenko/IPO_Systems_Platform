# Memory Isolation & Protection

IPO_OS implements a robust execution and stability model designed for bare-metal x86 hardware. Operating in flat 32-bit protected mode, the system protects kernel stability and isolates running tasks through **partitioned memory slicing**, **application storage swapping**, **dedicated workspace VRAM backups**, and **two-tier exception crash recovery**.

---

```
                                 │ process_map_app() swapping

```

## 🧠 1. Partitioned Dynamic Memory Slicing

To prevent user processes from colliding with the kernel heap or each other:
1. **Kernel Heap (`kmalloc`):** Allocated at `0x01000000` (16 MB) to `0x05000000` (80 MB) with **64 MB** (`0x04000000`) capacity.
2. **Process Heaps (`sbrk`):** Dynamic user allocations are partitioned into strictly isolated physical slots:
   `Base Address = USER_HEAP_START (0x08000000, or 0x05000000 on systems with 128 MB RAM or less) + slot * USER_HEAP_PROCESS_STRIDE (256 MB dynamic stride)`
   Slots are dynamically allocated as the first non-overlapping range, validated against E820 RAM capacity, and reclaimed immediately upon process termination.

---

## 🔄 2. Dynamic Memory Allocation in Free Space & Zero-Copy Switching

Instead of copying processes into a single static memory window, the kernel dynamically places processes into free memory:
- **First-Fit Memory Management (`allocate_process_memory`):** Finds the first available free memory block in the process heap pool (`PROCESS_HEAP_START = 0x00800000`) or appends to unallocated space, splitting blocks if larger than requested.
- **In-Place Execution:** The application's binary image is copied directly into the allocated memory block (`proc->binary_base = mem`), and `proc->entry_point` points to this address.
- **Zero-Copy Context Switching (`process_switch_context`):** CPU registers and stack pointers are switched directly without copying `.data`, `.bss`, or `.text` memory slices.
- **Block Coalescing (`coalesce_free_blocks`):** When processes exit, their memory blocks are released (`pid = 0`) and adjacent free blocks are merged automatically.

---

## 📺 3. Workspace & Terminal VRAM Isolation

Each process running in batch mode maintains an isolated virtual console and graphics context:
- **`text_vram_backup`:** Dedicated 80x25 character/attribute buffer (4000 bytes) + `text_output_buf` capture buffer.
- **Graphics State:** Dedicated `gfx_vram_backup` framebuffer backup and 256-color VGA DAC `gfx_palette_backup` (768 bytes).
- **Scrollback Buffers:** Top and bottom history buffers (`scroll_top_buffer`, `scroll_bottom_buffer`).
- **Cursor State:** Dedicated cursor coordinates and visibility flags.
Switching foreground processes immediately swaps the physical screen (`0xB8000` or `0xA0000`), preventing background processes from corrupting the display.

## 🚨 4. Two-Tier Exception Crash Recovery

CPU exceptions (vectors 0–31: Divide by Zero, Invalid Opcode, General Protection Fault) are intercepted by `cpu_exception_handler(uint32_t *frame)` in `src/kernel/syscall/syscall.c`:

1. **Process Crash Isolation:**
   If a fault occurs while executing user code (`proc != NULL`), the kernel logs the error (vector, name, EIP, error code) and modifies the saved return address:
   ```c
   frame[9] = (uint32_t)process_crash_exit;
   ```
   When `iretd` executes, the CPU enters `process_crash_exit`, cleaning up the crashed process and returning safely to the interactive shell without a kernel panic!
2. **Kernel Panic Boundary:**
   If an exception occurs within core kernel code (`proc == NULL`), the kernel logs a panic message to VGA and serial COM1, then executes `while(1) { __asm__ volatile("cli; hlt"); }`.

---

## 🔍 5. Syscall Parameter & Range Validation

All pointers passed into system calls via `ECX` (`const uint32_t *argv`) are verified by the kernel dispatcher:
- Null pointer detection.
- Buffer size and integer overflow checks.
- Invalid or unmapped filesystem paths reject with `-IPO_ERR_INVALID_PARAM` or `-IPO_ERR_BAD_ADDRESS`.
