## 📦 Подсистемы управления памятью

### 1. Менеджер физической карты памяти E820 (`src/kernel/mm/memory_map.c`)
Карта физической памяти и общий объём доступной RAM определяются MBR-загрузчиком в реальном режиме через вызовы BIOS `INT 15h, EAX=0xE820` (с резервным `AX=0xE801`):
- Загрузчик сохраняет массив **20-байтных** дескрипторов регионов `e820_entry_t` начиная с физического адреса **`0x6000`** и записывает заголовок `e820_map_header_t` в область `0x8FE0`–`0x8FF7` (сигнатура `'E820'` `0x45383230` в `0x8FE0`, количество записей в `0x8FE4`, указатель `0x00006000` в `0x8FE8`, суммарный объём RAM в `0x8FF0`/`0x8FF4`).
- Подсистема `memory_map_init()` парсит записи E820 (`E820_RAM`, `E820_RESERVED`, `E820_ACPI`, `E820_NVS`, `E820_BADMEM`), сохраняет их в саморасширяющийся массив, резервирует первые 64 МБ региона `0x01000000` под `kmalloc`, выделяет крупные физические блоки через `memory_map_alloc()` (начиная с `0x05000000`) и выводит телеметрию по командам `free` и `hardware memory`.

### 2. Динамическая куча ядра (`src/kernel/mm/kmalloc.c`)
Куча ядра инициализируется с базового физического адреса `0x01000000` (16 МБ) до `0x05000000` (80 МБ) с ёмкостью **64 МБ** (`KMALLOC_HEAP_SIZE = 0x04000000`) и защищена SMP-спинлоком `s_kmalloc_lock`:
- Каждый блок памяти имеет 16-байтный заголовок `kmalloc_block_t` с защитным магическим числом `0xDEADBEEF` (в активном состоянии) или `0xDEADC0DE` (после освобождения).
- Поддерживаются `kmalloc()`, `kcalloc()`, `krealloc()` и `kfree()`. Функция `kmalloc_coalesce_and_shrink()` автоматически объединяет соседние освобождённые блоки и уменьшает границу `heap_used`.

### 3. Куча и адресное пространство процессов (`sbrk` и `malloc`)
Пользовательские программы в IPO_OS (ELF32 и плоские `.bin`) загружаются универсальным загрузчиком `universal_exec_load()` по базовому адресу `0x00800000`.
- При вызове системного вызова `IPO_SYSCALL_SBRK` (`0x1045`) ядро динамически управляет границей `proc->user_heap_break`.
- Для полной изоляции памяти процессов каждому PID выделяется собственное окно **512 МБ** (`0x20000000`):
  `proc_base = 0x08000000 + (pid - 1) * 0x20000000`.
- Пользовательский аллокатор `malloc()` / `calloc()` / `realloc()` / `free()` (`applications/lib/libc/stdlib.c`) запрашивает память у `sbrk()` чанками кратно 64 КБ и маркирует блоки заголовком `block_hdr_t` с магическим числом `0x4D414C43` (`"MALC"`).

### 4. Архитектура саморасширяющихся динамических буферов (Без лимитов массивов)
Во всех ключевых подсистемах ядра IPO_OS полностью устранены жёсткие ограничения статических массивов в пользу динамических буферов (`krealloc`):
- **Сетевой стек (`net.c`):** Буфер приёма пакетов `rx_packet_buf` автоматически расширяется под кадр любого размера без ограничения 1536 байт.
- **Клавиатура (`keyboard.c`):** Динамическая очередь событий, динамические таблицы раскладок и саморасширяющийся битовый массив `key_state` (без лимита `NUM_KEYS = 128`).
- **Терминал и Shell (`terminal.c`):** Рабочий каталог `terminal_cwd`, история команд и буферы автодополнения динамически растут по мере необходимости.
- **Системные структуры:** Дескрипторы дисков ATA (`model`, `serial`), блочных устройств (`block_device_t`), таблиц разделов (`partition_table_t`), пула хранения (`storage_pool_t`), заголовков модулей KMOD (`kmod_header_t`), реестра оборудования (`device_node_t`) и таблиц SMP ACPI/MP (`acpi_rsdp_t`, `acpi_sdt_header_t`, `mp_floating_pointer_t`) хранят строки и массивы в динамически расширяемой памяти кучи.
