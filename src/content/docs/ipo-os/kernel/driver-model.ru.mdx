# Архитектура драйверов устройств

Драйверы устройств в IPO_OS функционируют на уровне ядра Ring 0, взаимодействуя напрямую с портами ввода-вывода x86, конфигурационным пространством PCI и аппаратными линиями прерываний IRQ.

---

## 🔌 Интерфейс регистрации драйверов

Подсистема драйверов (`src/include/kernel/driver.h`) предоставляет унифицированную структуру интерфейса устройства:

```c
typedef struct driver {
    char *name;
    char *description;
    uint32_t flags;

    /* Lifecycle callbacks */
    int (*init)(void);
    int (*cleanup)(void);

    /* Event hooks */
    void (*on_tick)(void);                                       /* called every timer tick */
    bool (*on_key)(uint8_t scancode, bool is_break);            /* called on key event; return true to consume */
    int  (*on_command)(const char *cmd, int argc, char **argv); /* custom shell command; return 0 if handled */
    char (*on_char_output)(char c);                             /* intercept / transform stdout chars */

    /* Custom device I/O */
    int (*read)(void *buffer, size_t size, uint32_t offset);
    int (*write)(const void *buffer, size_t size, uint32_t offset);
    int (*ioctl)(uint32_t cmd, void *arg);

    void *owner;                                                /* owner process_t pointer (for user-space drivers) */
    struct driver *next;
} driver_t;

int driver_register(driver_t *drv);
int driver_unregister(const char *name);
```

Пользовательские программы могут получать список и управлять драйверами через системные вызовы:
- `IPO_SYSCALL_DRIVER_REGISTER` (`0x1060`)
- `IPO_SYSCALL_DRIVER_UNREGISTER` (`0x1061`)
- `IPO_SYSCALL_DRIVER_LIST` (`0x1062`)

## 🛠️ Встроенные драйверы устройств

### 1. Драйвер дисков ATA / IDE (`src/drivers/storage/ata.c`)
- **Базовые порты:** Командный блок Primary IDE `0x1F0`–`0x1F7`, блок управления `0x3F6`; Secondary IDE `0x170`–`0x177`, `0x376`.
- **Адресация и динамические строки:** Режимы LBA28 и LBA48 через программный ввод-вывод (PIO). В структуре `ata_device_t` строки модели (`char *model`) и серийного номера (`char *serial`) выделяются динамически без фиксированных массивов.
- **Интеграция с `block_dev`:** Каждый обнаруженный накопитель автоматически регистрируется как блочное устройство (`ata0`, `ata1` и т. д.) и сканируется парсером разделов MBR/GPT (`partition_scan()`).

### 2. Драйвер сетевой карты Realtek RTL8139 PCI и динамический `rx_packet_buf`
- **Поиск на шине:** Сканирование конфигурационного пространства PCI (Vendor `0x10EC`, Device `0x8139`).
- **Буферы:** Настройка четырёх физических 2 КБ буферов отправки (`TSD0`–`TSD3`) и кольцевого буфера приёма RX (8 КБ + 16 байт). В сетевом стеке (`net.c`) приёмный буфер пакета `rx_packet_buf` автоматически расширяется через `krealloc` под размер любого входящего кадра без жёсткого лимита в 1536 байт.
- **Опрос и обработка:** Обработка событий успешного приёма (`ROK`) и передачи (`TOK`) со сбросом пакетов в стек TCP/IP.
- **Клиент DHCP (`src/net/dhcp.c`):** Автоматическое получение сетевой конфигурации через цикл DORA (Discover, Offer, Request, Ack) на портах UDP 67/68.

### 3. Подсистема ввода PS/2 и динамические таблицы клавиш
- **Контроллер 8042:** Порты `0x60` (данные) и `0x64` (статус/команды).
- **Динамические буферы без лимитов:** Очередь клавиатурных событий, таблицы раскладок и битовая карта зажатых клавиш `key_state` в `keyboard.c` динамически расширяются в куче (устранён фиксированный предел `NUM_KEYS = 128`). Поддерживается переключение раскладок через `IPO_SYSCALL_KEYMAP_CYCLE_NEXT` (`0x1058`).

### 4. Звуковая подсистема: Sound Blaster 16 и PC Speaker
- **Sound Blaster 16:** Базовый порт DSP `0x220`. Обмен командами и сброс через регистры буферов ввода-вывода `0x22C`/`0x22A`.
- **PC Speaker:** Канал 2 таймера PIT подключён к логическому вентилю порта динамика `0x61` (биты 0 и 1).

## 📦 Загрузчик релоцируемых модулей ядра (`KMOD`, `.kmd`)

Подсистема **KMOD** (`src/kernel/core/kmod.c`, `src/include/kernel/kmod.h`) позволяет загружать и выгружать скомпилированные бинарные модули ядра и драйверы (`.kmd`) прямо с файловой системы `IPO_FS` во время работы ОС:
- **Формат `.kmd` (`kmod_raw_header_t` / `kmod_header_t`):** Заголовок с магическим числом **`0x444D4B49` (`"IKMD"`)**, версией ABI **`0x0100`**, смещениями точек входа `init_offset` и `exit_offset`, таблицей импортируемых/экспортируемых символов и таблицей релокаций. В ОЗУ строки `name`, `description`, `author` и `version` хранятся в динамических буферах без фиксированных лимитов длины.
- **Двухпроходная генерация символов (`tools/generate_ksyms.py`):** При сборке ядра скрипт извлекает все глобальные функции и переменные из `nm` и генерирует таблицу `s_kernel_syms` (**~1560 экспортируемых символов ядра**), доступных через `kmod_resolve_symbol()`.
- **Релокации:** Загрузчик `kmod_load()` выделяет выровненную память для `.text/.data` и `.bss`, разрешает внешние символы ядра и применяет 32-битные абсолютные (`KMOD_RELOC_ABS32`) и относительные (`KMOD_RELOC_REL32`) релокации перед вызовом `init()`.

## 🧭 Единый реестр аппаратных устройств (`device.c`)

Подсистема **Device Registry** (`src/kernel/core/device.c`, `src/include/kernel/device.h`) объединяет все обнаруженные узлы оборудования в потокобезопасное дерево `device_node_t` (защищённое спинлоком `spinlock_t`):
- **Опрашиваемые шины и классы (без хардкода):** Прямое аппаратное сканирование шин PCI (чтение Option ROM, Expansion ROM, VPD 0x03, SMBIOS Type 9/41), ACPI DSDT AML, CPUID, E820 и накопителей ATA по серийным номерам и моделям из IDENTIFY (например, `QM00001`).
- **Горячее пересканирование:** Вызов `device_rescan()` повторно опрашивает шины PCI, ATA и USB, автоматически отмечая отключённые или новые устройства.

### Команды оболочки для управления драйверами, символами и оборудованием:
```bash
drivers list                    # Список всех встроенных драйверов и загруженных модулей .kmd
drivers load /path/module.kmd   # Динамическая загрузка и линковка модуля ядра .kmd
drivers unload <id|name>        # Вызов exit() и выгрузка модуля из памяти ядра
drivers info <id|name>          # Подробная информация о драйвере/модуле и его колбэках
drivers status                  # Сводка по числу драйверов, модулей и символов ядра
drivers symbols                 # Печать таблицы символов ядра (также: symbols / ksyms)
symbols [фильтр]                # Поиск по таблице ~1560 экспортируемых символов ядра (алиас: ksyms)
hardware overview               # Сводная таблица процессоров, памяти, шин и устройств
hardware list                   # Полный список всех зарегистрированных узлов оборудования
hardware cpu | memory           # Детальный статус ядер SMP / таблицы памяти E820 и пулов
hardware pci | storage | network | usb # Детальный список устройств по выбранному классу
hardware info <id>              # Подробный паспорт конкретного узла оборудования
hardware status                 # Статистика распределения устройств по состояниям и типам
hardware refresh                # Горячее пересканирование всех аппаратных шин
```
