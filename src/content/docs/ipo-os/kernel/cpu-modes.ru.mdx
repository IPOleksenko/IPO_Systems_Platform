# Режимы процессора, GDT и IDT

IPO_OS переводит процессор из 16-битного реального режима в 32-битный защищённый режим, формируя плоскую модель памяти на 4 ГБ с единой сегментацией и шлюзами векторов прерываний.

---

## 🎛️ Переход режимов процессора

```
┌──────────────────────────────────────────────┐
│           16-битный реальный режим           │
│  • 1 МБ физической адресации (Segment:Offset)│
│  • Сервисы BIOS (IVT INT 10h-1Ah)            │
│  • Определение RAM (E820 в ячейку 0x8FF0)    │
└──────────────────────┬───────────────────────┘
                       │ lgdt [gdt_desc], CR0.PE = 1, Far jmp 0x08:pmode_entry
┌──────────────────────▼───────────────────────┐
│     32-битный плоский защищённый режим       │
│  • Плоская физическая память 4 ГБ            │
│  • Base = 0x00000000, Limit = 4 ГБ (G=1)     │
│  • CS = 0x08, DS = ES = SS = FS = GS = 0x10  │
│  • Таблица IDT (256 шлюзов) со шлюзом 0x80  │
└──────────────────────────────────────────────┘
```

## 📑 Таблица глобальных дескрипторов (GDT)

В `src/boot/boot.asm` загрузчик создаёт постоянную плоскую таблицу GDT из 3 дескрипторов:

| Селектор | Индекс | Уровень привилегий | Тип сегмента | Базовый адрес | Предел | Гранулярность и флаги |
| :--- | :---: | :---: | :--- | :---: | :---: | :--- |
| **`0x00`** | 0 | — | Нулевой дескриптор | `0x00000000` | `0x00000` | Зарезервирован |
| **`0x08`** | 1 | Ring 0 | Сегмент кода (Execute/Read) | `0x00000000` | `0xFFFFF` | 4 КБ (`G=1`, 32-бит, `0x00CF9A000000FFFF`) |
| **`0x10`** | 2 | Ring 0 | Сегмент данных (Read/Write) | `0x00000000` | `0xFFFFF` | 4 КБ (`G=1`, 32-бит, `0x00CF92000000FFFF`) |

### Инициализация защищённого режима:
```asm
lgdt [gdt_desc]
mov eax, cr0
or eax, 1                      ; Бит 0: Protection Enable (PE)
mov cr0, eax
jmp 0x08:pmode_entry           ; Дальний переход сбрасывает конвейер инструкций

[BITS 32]
pmode_entry:
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov fs, ax
    mov gs, ax
    mov esp, 0x500000          ; Начальный стек ядра на 5 МБ
    jmp 0x00010000             ; Точка входа ядра _start
```

## ⚡ Таблица дескрипторов прерываний (IDT)

В `src/kernel/syscall/syscall.c` ядро формирует и загружает IDT на 256 шлюзов (`ipo_idt_table`):

- **Векторы `0x00`–`0x1F` (0–31):** Аппаратные исключения ЦП (`isr_0` .. `isr_31`), перенаправляемые в `cpu_exception_handler`.
- **Вектор `0x80` (128):** Шлюз прерываний системных вызовов (`IPO_IDT_ENTRY_FLAGS = 0xEE`), указывающий прямо на `syscall_isr_entry`.
- **Векторы `32`–`127` и `129`–`255`:** Не зарегистрированы (нулевые). Контроллер 8259 PIC не переназначается в защищённом режиме; всё периферийное оборудование обслуживается через неблокирующий опрос (polling) в главном цикле ядра `kmain()`.

Указатель IDT загружается инструкцией `lidt`:
```c
ipo_idt_ptr_t idt_ptr = {
    .limit = (uint16_t)(sizeof(ipo_idt_table) - 1),
    .base = (uint32_t)ipo_idt_table
};
__asm__ volatile("lidt %0" : : "m"(idt_ptr));
```
