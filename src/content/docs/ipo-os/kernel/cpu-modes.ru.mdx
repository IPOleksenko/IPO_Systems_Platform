# Режимы процессора, GDT и IDT

IPO_OS переводит процессор из 16-битного реального режима в 32-битный защищённый режим, формируя плоскую модель памяти на 4 ГБ с единой сегментацией и шлюзами векторов прерываний.

---

## 🎛️ Переход режимов процессора

```
┌──────────────────────────────────────────────┐
│           16-битный реальный режим           │
│  • 1 МБ физической адресации (Segment:Offset)│
│  • Сервисы BIOS (IVT INT 10h-1Ah)            │
│  • Определение RAM (E820 в 0x6000 / 0x8FE0)  │
└──────────────────────┬───────────────────────┘
                       │ lgdt [gdt_desc], CR0.PE = 1, Far jmp 0x08:pmode_entry
┌──────────────────────▼───────────────────────┐
│     32-битный плоский защищённый режим       │
│  • Плоская физическая память 4 ГБ            │
│  • Base = 0x00000000, Limit = 4 ГБ (G=1)     │
│  • CS = 0x08, DS = ES = SS = FS = GS = 0x10  │
│  • Таблица IDT (256 шлюзов) со шлюзом 0x80  │
└──────────────────────────────────────────────┘
```

## 📑 Таблица глобальных дескрипторов (GDT)

В `src/boot/boot.asm` загрузчик создаёт постоянную плоскую таблицу GDT из 3 дескрипторов:

| Селектор | Индекс | Уровень привилегий | Тип сегмента | Базовый адрес | Предел | Гранулярность и флаги |
| :--- | :---: | :---: | :--- | :---: | :---: | :--- |
| **`0x00`** | 0 | — | Нулевой дескриптор | `0x00000000` | `0x00000` | Зарезервирован |
| **`0x08`** | 1 | Ring 0 | Сегмент кода (Execute/Read) | `0x00000000` | `0xFFFFF` | 4 КБ (`G=1`, 32-бит, `0x00CF9A000000FFFF`) |
| **`0x10`** | 2 | Ring 0 | Сегмент данных (Read/Write) | `0x00000000` | `0xFFFFF` | 4 КБ (`G=1`, 32-бит, `0x00CF92000000FFFF`) |

### Инициализация защищённого режима:
```asm
lgdt [gdt_desc]
mov eax, cr0
or eax, 1                      ; Бит 0: Protection Enable (PE)
mov cr0, eax
jmp 0x08:pmode_entry           ; Дальний переход сбрасывает конвейер инструкций

[BITS 32]
pmode_entry:
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov fs, ax
    mov gs, ax
    mov esp, 0x500000          ; Начальный стек ядра на 5 МБ
    jmp 0x00010000             ; Точка входа ядра _start
```

## ⚡ Таблица дескрипторов прерываний (IDT)

В `src/kernel/syscall/syscall.c` ядро формирует и загружает IDT на 256 шлюзов (`ipo_idt_table`):

- **Векторы `0x00`–`0x1F` (0–31):** Аппаратные исключения ЦП (`isr_0` .. `isr_31`), перенаправляемые в `cpu_exception_handler`.
- **Вектор `0x80` (128):** Шлюз прерываний системных вызовов (`IPO_IDT_ENTRY_FLAGS = 0xEE`), указывающий прямо на `syscall_isr_entry`.
- **Векторы `32`–`127` и `129`–`255`:** Не зарегистрированы (нулевые). Контроллер 8259 PIC не переназначается в защищённом режиме; всё периферийное оборудование обслуживается через неблокирующий опрос (polling) в главном цикле ядра `kmain()`.

Указатель IDT загружается инструкцией `lidt`:
```c
ipo_idt_ptr_t idt_ptr = {
    .limit = (uint16_t)(sizeof(ipo_idt_table) - 1),
    .base = (uint32_t)ipo_idt_table
};
__asm__ volatile("lidt %0" : : "m"(idt_ptr));
```

## 🔥 Симметричная многопроцессорность (SMP) и Local APIC

Подсистема SMP (`src/kernel/arch/x86/smp.c`, `smp_trampoline.asm`, `src/include/kernel/smp.h`) обеспечивает обнаружение всех физических и логических ядер процессора, инициализацию контроллера Local APIC и запуск вторичных процессоров (**Application Processors, AP**).

### 1. Обнаружение топологии CPU и динамические дескрипторы ACPI / MP
При вызове `smp_init()` загрузочное ядро (**BSP — Bootstrap Processor**) определяет конфигурацию ядер в три этапа:
1. **Таблицы ACPI (RSDP → RSDT → MADT / `APIC`):** Поиск сигнатуры `"RSD PTR "` в области EBDA и `0xE0000`–`0xFFFFF`, проверка контрольных сумм и обход записей Local APIC (Type 0) в таблице MADT.
2. **Intel MP Floating Pointer (`_MP_`):** Резервный парсинг таблиц спецификации Intel Multiprocessor 1.1/1.4.
3. **Опрос `CPUID`:** Резервное определение числа логических ядер и динамическое извлечение строк производителя (`smp_get_cpu_vendor`), модели (`smp_get_cpu_brand`) и поддерживаемых инструкций (`smp_get_cpu_features_str`: `FPU`, `TSC`, `MSR`, `PAE`, `APIC`, `MMX`, `SSE`, `SSE2`, `SSE3`, `SSSE3`, `SSE4.1`, `SSE4.2`, `AVX`, `LM(x64)`).

> **Отсутствие фиксированных лимитов массивов:** Все дескрипторы таблиц в памяти (`acpi_rsdp_t`, `acpi_sdt_header_t`, `acpi_madt_t`, `mp_floating_pointer_t`), а также реестр процессоров `s_cpus` используют саморасширяющиеся динамические буферы в куче (`char *` / `uint8_t *` + `_len` + `_cap` через `krealloc`) без жёстких ограничений размера.

### 2. Инициализация Local APIC (`0xFEE00000`)
- Контроллер Local APIC включается установкой бита 11 (`APIC_BASE_ENABLE_BIT`) в моделезависимом регистре `IA32_APIC_BASE_MSR` (`0x1B`).
- Регистр ложных прерываний **SVR** (`0x00F0`) активируется маской `0x1FF` (бит 8 Software Enable + вектор `0xFF`), а регистр приоритета задач **TPR** (`0x0080`) сбрасывается в `0`.

### 3. Пробуждение вторичных ядер (AP Trampoline `0x8000` и `INIT-SIPI-SIPI`)
Для каждого обнаруженного вторичного ядра (AP) ядро выделяет 16 КБ стека из `kmalloc` и копирует позиционно-независимый 16/32-битный трамплин (`smp_trampoline.asm`) по физическому адресу **`0x00008000`**:
- **Почтовый ящик трамплина (`0x80F0`–`0x80FC`):**
  - `0x80F0` (`SMP_BOOT_STACK_ADDR`) — вершина выделенного 16 КБ стека для запускаемого AP.
  - `0x80F4` (`SMP_BOOT_CPUID_ADDR`) — логический индекс `cpu_id`.
  - `0x80F8` (`SMP_BOOT_FN_ADDR`) — адрес точки входа C-функции `smp_ap_entry()`.
  - `0x80FC` (`SMP_BOOT_DONE_ADDR`) — флаг подтверждения (`1` после перехода AP в 32-битный режим).
- **Последовательность `INIT-SIPI-SIPI`:** BSP отправляет целевому AP сигнал `INIT` (`0x00004500`) через регистры `LAPIC_ICR_HIGH` (`0x0310`) / `LAPIC_ICR_LOW` (`0x0300`), выдерживает паузу 10 мс и дважды отправляет `SIPI` (`0x00004608`, вектор страницы `0x08` = `0x8000 >> 12`).
- Проснувшееся ядро AP в `0x8000` загружает временную GDT, включает бит `CR0.PE`, прыгает в 32-битный код, настраивает свой `ESP` из `0x80F0`, устанавливает флаг `0x80FC = 1`, загружает общую IDT ядра, инициализирует свой Local APIC и переходит в рабочий цикл ожидания задач `smp_ap_entry()`.

### 4. Спинлоки (`spinlock_t`) и межъядерные задачи (`smp_broadcast_task`)
- Для синхронизации потоков между ядрами в `src/include/kernel/smp.h` реализованы атомарные спинлоки (`spinlock_acquire`, `spinlock_release`, `spinlock_irqsave`, `spinlock_irqrestore`) на базе `__atomic_test_and_set` с инструкцией `pause`.
- Функция `smp_broadcast_task(fn, arg)` позволяет параллельно выполнить callback-задачу на всех активных ядрах системы с барьерным ожиданием завершения и отправкой межъядерных прерываний IPI (`SMP_IPI_VECTOR = 0xE0`).
