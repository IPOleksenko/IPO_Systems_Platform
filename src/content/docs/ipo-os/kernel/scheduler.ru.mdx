# Планировщик процессов и потоков

Подсистема планирования IPO_OS управляет многозадачностью с помощью **гибридного кооперативно-квантованного диспетчера** с поддержкой пакетных конвейеров задач, изоляции рабочих пространств и асинхронных фоновых обработчиков.

## 📋 Блок управления процессом (`process_t`)

Каждый процесс в IPO_OS описывается структурой `process_t` в `src/include/kernel/process.h`:

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| **`pid`** | `uint32_t` | Уникальный идентификатор процесса |
| **`binary_base`** | `void *` | Базовый адрес исполнения (`0x800000` / `PROCESS_HEAP_START`) |
| **`binary_size`** | `uint32_t` | Полный размер исполняемого образа |
| **`entry_point`** | `uint32_t` | Абсолютная точка входа программы (`_start`) |
| **`binary_storage`**| `void *` | Выделенный буфер сохранения при вытеснении процесса |
| **`data_offset`** | `uint32_t` | Смещение изменяемых сегментов `.data` и `.bss` |
| **`data_size`** | `uint32_t` | Размер изменяемых данных для сохранения |
| **`stack_base`** | `void *` | Базовый адрес выделенного стека процесса |
| **`stack_ptr`** | `uint32_t` | Сохранённый указатель `%esp` при смене контекста |
| **`exit_code`** | `int` | Код завершения процесса |
| **`is_running`** | `uint8_t` | Флаг активного исполнения |
| **`waiting_for_input`**| `bool` | Флаг блокировки при ожидании нажатия клавиши |
| **`text_vram_backup`** | `uint16_t *` | Копия видеопамяти 80x25 для изоляции рабочего пространства |
| **`user_heap_break`** | `uint32_t` | Текущий указатель границы кучи процесса (`sbrk`) |

## ⚡ Переключение контекста (`process_switch_context`)

Переключение контекста между процессами выполняется функцией на чистом ассемблере в `src/kernel/core/process.c`:

```c
__attribute__((naked)) static void process_switch_context(uint32_t *old_esp, uint32_t new_esp) {
    __asm__ volatile(
        "pushl %ebp\n\t"
        "pushl %ebx\n\t"
        "pushl %esi\n\t"
        "pushl %edi\n\t"
        "pushfl\n\t"
        "movl 24(%esp), %eax\n\t"    /* указатель old_esp */
        "movl 28(%esp), %edx\n\t"    /* значение new_esp */
        "movl %esp, (%eax)\n\t"      /* сохраняем текущий ESP */
        "movl %edx, %esp\n\t"        /* загружаем целевой ESP */
        "popfl\n\t"
        "popl %edi\n\t"
        "popl %esi\n\t"
        "popl %ebx\n\t"
        "popl %ebp\n\t"
        "ret\n\t"
    );
}
```

## ⏱️ Квантование 10 мс по `rdtsc` (`timer_tick`)

Помимо добровольной передачи управления через `IPO_SYSCALL_PROCESS_YIELD` (`0x1023`), ядро реализует квантование времени:

1. Таймер PIT настроен на частоту **1000 Гц** (шаг `1 мс`).
2. Модуль таймера (`src/kernel/arch/x86/timer.c`) считывает такты ЦП инструкцией `rdtsc`.
3. Каждые **10 мс** (`timer_ms - last_slice_yield_ms >= 10u`), если процессор находится в контексте процесса и вывод в консоль не заблокирован, `timer_tick()` автоматически вызывает `process_yield_kernel()`.
4. Это возвращает управление в планировщик ядра (`scheduler_esp`), передавая очередь следующему процессу пакета!

## 🔄 Асинхронные фоновые задачи (`async.c`)

Периодические фоновые задачи регистрируются системным вызовом `IPO_SYSCALL_ASYNC_START` (`0x1030`):
- Описываются структурами `async_task_t` с указателем на функцию `fn`, интервалом `interval_ms` и владельцем `owner`.
- Диспетчер `async_scheduler_tick()` проверяет тайминги и вызывает готовые задачи в основном цикле ядра.
