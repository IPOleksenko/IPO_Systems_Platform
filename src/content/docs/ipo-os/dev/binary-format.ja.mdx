# Binary Layout & Memory Map

IPO_OS implements a **universal executable loader** (`universal_exec_load()` in `src/kernel/core/process.c`). The kernel transparently loads both **32-bit ELF executables** (`0x7F 'E' 'L' 'F'`, mapping `PT_LOAD` segments and zero-filling `.bss` between `p_filesz` and `p_memsz`) and **raw flat binaries** (`.bin`) linked to start execution at address `0x00800000` (`PROCESS_HEAP_START`, 8 MB), as well as `#!` shebang scripts.

---

## 🗺️ Process Memory Map

Every user application in IPO_OS executes in a 32-bit flat address space:

```
+----------------------------------------------------+ Top of RAM
| Per-Process Dynamic Heaps (0x08000000 + (pid-1)*512M)|
+----------------------------------------------------+ 0x08000000 (128 MB)
| PMM Page Frame Pool (memory_map_alloc)             |
+----------------------------------------------------+ 0x05000000 (80 MB)
| Kernel Dynamic Heap (kmalloc, 64 MB capacity)      |
|   • Process Stacks (256 KB dynamic via setup_stack)|
|   • Process Arguments Array (argv) & Environment   |
+----------------------------------------------------+ 0x01000000 (16 MB)
| .bss (Zero-initialized variables)                  |
+----------------------------------------------------+
| .data (Initialized global and static variables)    |
+----------------------------------------------------+
| .rodata (String literals and constant pools)       |
+----------------------------------------------------+
| .text (Executable instructions, _start at entry)   |
+----------------------------------------------------+ 0x00800000 (8 MB)
| Kernel Space (Code at 0x10000, Stack at 0x500000)   |
| E820 map at 0x6000, RAM detection header at 0x8FE0 |
+----------------------------------------------------+ 0x00000000
```

## 📦 Supported Executable Formats

### 1. 32-bit ELF Executables (`ET_EXEC`, `EM_386`)
When `universal_exec_load()` detects the `0x7F 'E' 'L' 'F'` magic header, it parses the `Elf32_Phdr` program header table:
- Every `PT_LOAD` segment is loaded at its target `p_vaddr`.
- Any region where `p_memsz > p_filesz` (`.bss`) is automatically zero-initialized.
- **DWARF Return Reflection:** The loader parses `.debug_info`, `.debug_abbrev`, and `.debug_str` sections to automatically extract `main()`'s return type signature (`int`, `char*`, structs, arrays) for seamless typed data passing in multitasking pipelines (`run`).
- Segment permission flags (`PF_R`, `PF_W`, `PF_X`) are tracked, and the highest segment end sets the initial `program_break` for `sbrk()`.
- Execution jumps directly to `ehdr->e_entry`.

### 2. Raw Flat Binary (`.bin`)
A raw flat binary (`.bin`) contains no ELF headers and is loaded contiguously at `0x00800000`:

```
Offset in .bin      Section          Description
0x00000000          .entry / .text   Startup instructions (_start -> main)
+0x00000020          .text            Compiled functions
...                  .rodata          Constants, format strings
...                  .data            Pre-initialized global variables
...                  .bss             Included as zero-filled padding
```

## ⚙️ Linker Scripts & Startup Stubs (`crt0.s` / `entry.s`)

Two linker and startup profiles are provided:
1. **Full `libipo_c.a` Userland Runtime (`applications/lib/linker.ld` + `applications/lib/crt/crt0.s`):**
   - Zeroes `.bss` (`__bss_start` .. `__bss_end`), initializes `environ`, invokes `.preinit_array` and `.init_array` constructors, calls `main(argc, argv, environ)`, runs `.fini_array` destructors, and invokes `_exit(ret)`.
2. **Minimal Profile (`applications/app.ld` + `applications/entry.s`):**

```c
ENTRY(_start)

SECTIONS
{
    . = 0x800000;

    .text : ALIGN(4) {
        *(.entry)
        *(.text.startup)
        *(.text.main)
        *(.text*)
    }

    .rodata : ALIGN(4) { *(.rodata*) }
    .data   : ALIGN(4) { *(.data*) }
    .bss    : ALIGN(4) {
        __bss_start = .;
        *(COMMON)
        *(.bss*)
        __bss_end = .;
    }
    _end = .;
}
```

The entry point `applications/entry.s`:
```asm
.global _start
.extern main

.section .entry, "ax"
_start:
    jmp main
```

## ⚠️ The `.bss` Section in Flat `.bin` Images

When extracting a raw flat binary (`.bin`) via `objcopy`, include `.bss` as zero-filled bytes (or link with `crt0.s`, which zeroes `__bss_start .. __bss_end` at startup):

```bash
objcopy --set-section-flags .bss=alloc,load,contents \
        -j .text -j .rodata -j .data -j .bss \
        -O binary app.elf app.bin
```
