# Отладка приложений

Когда приложение выполняет недопустимую инструкцию или вызывает необработанное исключение, IPO_OS перехватывает сбой, отображает диагностическую телеметрию и корректно завершает аварийный процесс без падения операционной системы.

---

## 💥 Анатомия аварийного завершения процесса

Когда программа вызывает исключение процессора, диспетчер `cpu_exception_handler()` в ядре перехватывает его:

```
[Process 1] Terminated: CPU Exception 0 (Divide-by-zero (#DE)) at 0x00801248 (err=0x0)
```

Отчёт о сбое содержит:
- **PID процесса:** идентификатор аварийного процесса.
- **Вектор и имя исключения CPU:** например, Exception 0 (`Divide-by-zero`), Exception 6 (`Invalid Opcode`), Exception 13 (`General Protection Fault`).
- **Адрес сбоя EIP:** точный адрес инструкции в памяти, на которой возникло исключение (например, `0x00801248`).
- **Код ошибки (Error Code):** аппаратный код ошибки, переданный архитектурой CPU.

### Автоматический возврат в командную строку
Ядро подменяет адрес возврата стека на `process_crash_exit`, благодаря чему ресурсы процесса освобождаются, состояние терминала восстанавливается, и управление мгновенно возвращается в шелл (`> `).

## 🔍 Поиск места падения с помощью `addr2line` и `objdump`

Чтобы сопоставить адрес `EIP` с исходным кодом:

```bash
# 1. Преобразование hex-адреса в имя файла и номер строки
addr2line -e build/my_app.elf 0x00801248

# 2. Просмотр ассемблерного дизассемблирования вокруг адреса падения
objdump -d -S build/my_app.elf | grep -B 5 -A 10 "801248:"
```

## 🪲 Интерактивная отладка с GDB в QEMU

Поскольку приложения загружаются по фиксированному базовому адресу `0x00800000`, вы можете пошагово отлаживать их в реальном времени через GDB:

```bash
# 1. Запуск QEMU с остановкой CPU и ожиданием GDB на порту 1234
make run QEMU_FLAGS="-s -S"

# 2. В другом терминале подключите gdb
gdb -q
(gdb) target remote localhost:1234
(gdb) add-symbol-file build/my_app.elf 0x800000
(gdb) break main
(gdb) continue
```

## 🛡️ Пользовательский макрос `assert`

Чтобы предотвратить развитие скрытых ошибок в сбои ядра, используйте макрос проверки условий:

```c
#include <stdio.h>
#include <syscall.h>

#define assert(condition) \
    do { \
        if (!(condition)) { \
            printf("[ASSERT FAILED] %s:%d: %s\n", __FILE__, __LINE__, #condition); \
            ipo_exit(1); \
        } \
    } while (0)
```
