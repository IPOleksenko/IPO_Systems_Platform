# Формат бинарных файлов и карта памяти

В IPO_OS реализован **универсальный загрузчик исполняемых файлов** (`universal_exec_load()` в `src/kernel/core/process.c`). Ядро прозрачно поддерживает как **32-битные исполняемые файлы ELF** (`0x7F 'E' 'L' 'F'`, сегменты `PT_LOAD` с автоматическим обнулением `.bss` между `p_filesz` и `p_memsz`), так и **чистые плоские бинарные образы** (`.bin`), скомпонованные для исполнения по адресу `0x00800000` (`PROCESS_HEAP_START`, 8 МБ), а также исполняемые скрипты с заголовком `#!` (shebang).

---

## 🗺️ Карта памяти процесса

Каждое приложение в IPO_OS выполняется в плоском 32-битном адресном пространстве:

```
+----------------------------------------------------+ Верхняя граница RAM
| Секционированные кучи (0x08000000 + (pid-1)*512M)  |
+----------------------------------------------------+ 0x08000000 (128 МБ)
| Пул физических фреймов PMM (memory_map_alloc)      |
+----------------------------------------------------+ 0x05000000 (80 МБ)
| Динамическая куча ядра (kmalloc, 64 МБ)            |
|   • Стеки процессов (256 КБ через setup_stack)     |
|   • Массив аргументов процесса (argv) и окружение  |
+----------------------------------------------------+ 0x01000000 (16 МБ)
| .bss (Неинициализированные глобальные переменные)   |
+----------------------------------------------------+
| .data (Инициализированные переменные)              |
+----------------------------------------------------+
| .rodata (Строковые константы и литералы)           |
+----------------------------------------------------+
| .text (Исполняемый код, точка входа _start)        |
+----------------------------------------------------+ 0x00800000 (8 МБ)
| Память ядра (Код в 0x10000, стек ядра в 0x500000)  |
| Карта E820 в 0x6000, заголовок RAM в 0x8FE0        |
+----------------------------------------------------+ 0x00000000
```

## 📦 Поддерживаемые форматы исполняемых файлов

### 1. 32-битный ELF (`ET_EXEC`, `EM_386`)
При обнаружении сигнатуры `0x7F 'E' 'L' 'F'` загрузчик `universal_exec_load()` парсит таблицу заголовков программ (`Elf32_Phdr`):
- Все сегменты `PT_LOAD` копируются по своим физическим/виртуальным адресам `p_vaddr`.
- Область `p_memsz > p_filesz` (секция `.bss`) автоматически заполняется нулями.
- Для каждого сегмента учитываются флаги прав доступа (`PF_R`, `PF_W`, `PF_X`), а конец самого верхнего сегмента сохраняется как начальный `program_break` для `sbrk()`.
- Управление передаётся напрямую на точку входа `ehdr->e_entry`.

- **Интроспекция DWARF:** Ядро парсит секции `.debug_info`, `.debug_abbrev` и `.debug_str`, автоматически извлекая сигнатуру типа возврата `main()` (`int`, `char*`, структуры, массивы) для конвейерной передачи данных через `run`.

### 2. Плоский бинарный образ (`.bin`)
Плоский бинарный файл (`.bin`) не содержит заголовков ELF и загружается целиком по адресу `0x00800000`:

```
Смещение в .bin     Секция           Описание
0x00000000          .entry / .text   Точка входа (_start -> main)
+0x00000020          .text            Скомпилированные функции
...                  .rodata          Константы и строки
...                  .data            Инициализированные переменные
...                  .bss             Включена в виде заполнения нулями
```

## ⚙️ Скрипты компоновщика и точки входа (`crt0.s` / `entry.s`)

В репозитории доступны два профиля компоновки пользовательских программ:
1. **Полноценный рантайм `libipo_c.a` (`applications/lib/linker.ld` + `applications/lib/crt/crt0.s`):**
   - Очищает `.bss` (`__bss_start` .. `__bss_end`), инициализирует указатель `environ`, вызывает конструкторы из `.preinit_array` и `.init_array`, передаёт управление в `main(argc, argv, environ)`, а после возврата вызывает деструкторы `.fini_array` и системный вызов `_exit(ret)`.
2. **Минимальный профиль (`applications/app.ld` + `applications/entry.s`):**

```c
ENTRY(_start)

SECTIONS
{
    . = 0x800000;

    .text : ALIGN(4) {
        *(.entry)
        *(.text.startup)
        *(.text.main)
        *(.text*)
    }

    .rodata : ALIGN(4) { *(.rodata*) }
    .data   : ALIGN(4) { *(.data*) }
    .bss    : ALIGN(4) {
        __bss_start = .;
        *(COMMON)
        *(.bss*)
        __bss_end = .;
    }
    _end = .;
}
```

Точка входа `applications/entry.s`:
```asm
.global _start
.extern main

.section .entry, "ax"
_start:
    jmp main
```

## ⚠️ Секция `.bss` при сборке плоских `.bin`

При сборке в чистый плоский бинарник (`.bin`) утилита `objcopy` инструктируется принудительно включить секцию `.bss` в виде нулевых байтов (либо используется `crt0.s`, обнуляющий `__bss_start .. __bss_end` при старте):

```bash
objcopy --set-section-flags .bss=alloc,load,contents \
        -j .text -j .rodata -j .data -j .bss \
        -O binary app.elf app.bin
```
