# Руководство по стилю и частые ошибки

Разработка программного обеспечения для независимой операционной системы без стандартных сред выполнения (freestanding bare-metal) требует строгости и дисциплины. Ниже приведены ключевые рекомендации и типичные ошибки, которых следует избегать.

---

## 🚫 Главные ошибки при разработке под IPO_OS

### 1. Превышение лимитов стека
Ядро динамически выделяет стек размером 256 КБ для каждого процесса в куче `kmalloc`. Большие буферы данных всегда должны выделяться в куче процесса (`malloc` через `sbrk`):

```c
// ❌ НЕПРАВИЛЬНО: Выделение огромных массивов на стеке
void process_image(void) {
    char image_buffer[2 * 1024 * 1024]; // Переполняет стек и затирает код программы!
}

// ✅ ПРАВИЛЬНО: Выделение больших буферов в динамической памяти
void process_image(void) {
    char *image_buffer = (char *)malloc(2 * 1024 * 1024);
    if (!image_buffer) return;
    // ...
    free(image_buffer);
}
```

## 2. Игнорирование кодов возврата системных вызовов
Системные вызовы сообщают об ошибках через отрицательные возвращаемые значения. Никогда не полагайтесь на то, что вызов завершился успешно по умолчанию:

```c
// ❌ НЕПРАВИЛЬНО
int fd = ipo_open("/etc/config.cfg");
ipo_read(fd, buffer, 128, 0);

// ✅ ПРАВИЛЬНО
int fd = ipo_open("/etc/config.cfg");
if (fd < 0) {
    printf("Не удалось открыть файл: %d\n", fd);
    return;
}
```

---

## 3. Холостые циклы ожидания (Busy Loops), сжигающие процессор
В одноядерной конфигурации зависание в пустом цикле блокирует фоновые задачи ядра:

```c
// ❌ НЕПРАВИЛЬНО: Тратит 100% процессорного времени впустую
while (!ready) {}

// ✅ ПРАВИЛЬНО: Передавайте управление другим процессам через yield
while (!ready) {
    ipo_syscall(IPO_SYSCALL_PROCESS_YIELD, 0, NULL);
}
```

---

## 4. Потеря секции `.bss` в плоских бинарных файлах
Поскольку в «сырых» плоских бинарных образах (flat binary) отсутствуют заголовки сегментов ELF, убедитесь, что секция `.bss` включена в образ при конвертации через `objcopy`:
```bash
objcopy -O binary --set-section-flags .bss=alloc,load,contents app.elf app.bin
```

---

## 5. Обращение к памяти ниже адреса `0x800000`
Адреса ниже `0x00800000` зарезервированы под код ядра, его структуры данных и буферы ввода-вывода. Запись в эту область приведёт к повреждению состояния ядра.

---

## 6. Утечки дескрипторов файлов
Каждый успешный вызов `ipo_open()` должен обязательно завершаться вызовом `ipo_close()` во всех ветках выполнения функции.
