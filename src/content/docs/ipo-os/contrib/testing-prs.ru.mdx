# Тестирование и Pull Requests

Перед отправкой патчей или открытием Pull Request в репозиторий IPO_OS убедитесь, что ваши изменения компилируются без предупреждений и успешно проходят запуск без графического интерфейса (headless) в QEMU.

---

## 🧪 Запуск тестов в QEMU без дисплея (Headless)

IPO_OS может быть запущена в headless-режиме с выводом последовательного порта COM1 в стандартный поток вывода (stdout):

```bash
# Запуск тестирования без графического интерфейса с подключением загрузочного диска и диска данных
qemu-system-i386 -m 2048 \
    -drive format=raw,file=build/IPO_OS.img,if=ide,index=0 \
    -drive format=raw,file=build/disk.img,if=ide,index=1 \
    -display none -serial stdio
```

## 📝 Соглашения об оформлении коммитов

Мы придерживаемся спецификации **Conventional Commits**:
```
<type>(<scope>): <краткое описание в повелительном наклонении>

[опциональное подробное описание причин и контекста изменений]
```

### Основные типы коммитов:
- `feat`: новая функция ядра или модуль драйвера
- `fix`: исправление ошибки в существующем коде
- `docs`: обновление или добавление документации
- `refactor`: реорганизация кода без изменения функциональности
- `test`: добавление или обновление тестов

## ✅ Чек-лист проверки перед Pull Request

Перед передачей PR на ревью проверьте:
1. [ ] Исходный код компилируется без предупреждений (`make all`).
2. [ ] Ядро стабильно загружается до интерактивной командной строки (`> `).
3. [ ] Отсутствуют утечки памяти в пулах кучи `kmalloc`.
4. [ ] Все изменённые системные вызовы строго соответствуют ABI указателя на массив аргументов в `<syscall.h>`.
