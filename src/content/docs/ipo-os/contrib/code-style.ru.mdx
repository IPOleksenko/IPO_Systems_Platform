# Руководство по стилю кода ядра

Для поддержания читаемости и архитектурной целостности всех модулей ядра и драйверов разработчики должны соблюдать описанные ниже соглашения.

---

## 🖋️ Стандарты языка C

Исходный код IPO_OS придерживается классического стиля ядра Linux (**Linux Kernel C style**) с отступами в 4 пробела:
- Используйте **4 пробела** для отступов (в исходных файлах C табуляция не используется; в Makefile сохраняются стандартные символы табуляции).
- Для функций открывающая и закрывающая фигурные скобки помещаются на отдельных строках:
```c
int ipo_fs_mount(uint64_t disk_start_lba)
{
    if (disk_start_lba == 0) {
        return 0;
    }
    return do_mount(disk_start_lba);
}
```
- Для управляющих конструкций (`if`, `for`, `while`, `switch`) открывающая скобка располагается на той же строке.

---

## 🏷️ Соглашения об именовании

### Префиксы подсистем
Публичные символы ядра должны начинаться с префикса соответствующей подсистемы:
- `process_*` — диспетчер процессов и планировщик (`process_create`, `process_yield_kernel`, `process_switch_context`)
- `kmalloc` / `kfree` — динамический распределитель памяти кучи ядра
- `ipo_fs_*` — файловая система IPO_FS (`ipo_fs_mount`, `ipo_fs_format`, `ipo_fs_read`)
- `driver_*` — подсистема драйверов устройств (`driver_register`, `driver_unregister`)
- `vga_*` — текстовые и графические функции VGA
- `ipo_*` — глобальные API операционной системы и пользовательские обёртки системных вызовов

### Типы и макросы
- Используйте типы фиксированной ширины из `<stdint.h>` (`uint8_t`, `uint16_t`, `uint32_t`, `uint64_t`).
- Определения типов структур должны оканчиваться суффиксом `_t` (например, `process_t`, `driver_t`, `ipo_inode_t`).
- Константы и макросы должны быть написаны в `ВЕРХНЕМ_РЕГИСТРЕ` (например, `IPO_SYSCALL_PRINT`).

## ⚡ Форматирование ассемблерного кода (NASM и AT&T)

- Отдельные файлы `.asm` используют **синтаксис Intel для NASM** с именами регистров в нижнем регистре:
```asm
bits 32
section .text
global syscall_isr_entry

syscall_isr_entry:
    push ebx
    push ecx
    push edx
    push esi
    push edi
    push ebp
    call syscall_dispatch
    pop ebp
    pop edi
    pop esi
    pop edx
    pop ecx
    pop ebx
    iretd
```
- Встроенный ассемблер (inline assembly) в исходных текстах на C использует стандартный **синтаксис GNU AT&T** с явным указанием ограничений операндов и списков перезаписываемых регистров (clobbers).
